# История изменений Pushok VPN

Формат версий: X.YYY. Новые версии добавляются сверху.

## [Unreleased]

- Кабинет: быстрые переходы к подключениям, заказам и поддержке с переносом фокуса для клавиатуры.

- Telegram Mini App: добавлена нижняя навигация по главной, тарифам, кабинету и помощи; активный раздел подсвечивается при прокрутке.
- Telegram Mini App следует светлой/тёмной теме Telegram; окна и уведомления учитывают высоту экрана и безопасные отступы. Оформление магазина в браузере не меняется.
- Telegram Mini App: системная кнопка «Назад» закрывает верхнее открытое окно магазина и скрывается на главном экране. В обычном браузере поведение не меняется.
- Добавлено необязательное задание WGDashboard для удаления peer по сроку подписки. JobID сохраняется между попытками, активная задача обновляется при продлении, результат сверяется до выдачи конфига. В админке можно задать часовой пояс ОС панели; обычный worker магазина остаётся основным механизмом отключения. Реальная панель требует стендовой приёмки.
- Завершена форма подключения WGDashboard: выбор панели, API-ключ, интерфейс, проверка смены режима и сохранение существующего профиля при редактировании. Подсказки Remnawave скрываются при выборе WireGuard.
- Исправлен Docker staging: новая таблица ключей допускается только пустой при первом обновлении; проверки изменения/потери существующих ключей сохранены. Добавлен тест расшифровки ключа после резервного копирования и восстановления.

- Remnawave v3: адаптер сверён с официальной документацией и исходниками backend; добавлены подтверждение внутренних групп, строгая идентичность при отключении и сравнение эквивалентных UTC дат. Добавлены контрактные тесты создания/продления/отключения/повтора и инструкция `docs/REMNAWAVE.md`; режим явно подписан в админке. Реальная панель и трафик не проверялись.

- WGDashboard подключён к серверному сценарию заказа через явный профиль API: выдача конфига, повторное использование ключа при продлении и отзыв worker после срока. Неизвестный режим и смена привязанного интерфейса запрещены; автономный срок на стороне панели пока не реализован. Реальная приёмка остаётся открытой.

- WGDashboard: зашифрованное постоянное хранение ключей до сетевой записи и получение конфига с проверкой идентичности и структуры; добавлены тесты миграции, повторов, неверных привязок и небезопасных шаблонов. Подключение к заказам и срокам доступа ещё не выполнено.

- WGDashboard: добавлены отдельные методы создания peer по заранее сохранённому ключу и удаления с повторным чтением результата; тесты потерянного ответа, повторов и ограниченного peer. К заказам и срокам подписок пока не подключены.

- Добавлена отдельная проверка API WGDashboard через `panel_check.py --wgdashboard`: ключ, схема ответа и выбранный активный WG-интерфейс; без записи peers и включения продаж. Документация: `docs/WGDASHBOARD.md`.

- Уведомление ЮKassa об отмене теперь получает HTTP 503, пока независимая проверка Merchant API оставляет заказ в pending. Это запрашивает повтор уведомления так же, как для успешной оплаты.
- Добавлены проверки задержанного подтверждения для обоих событий, повторной доставки и отсутствия повторного запроса после отмены. Реальный Merchant API и VPS не проверялись.

## [0.054] — 2026-11-10

- Добавлена явная оплата через СБП для email-клиентов: `PAYMENT_MODE=sbp`, отдельное значение метода заказа и `payment_method_data.type=sbp` в API ЮKassa, с прежними Redirect/capture/idempotence.
- Telegram Stars сохранены отдельно от рублёвых оплат. Публичный каталог и экран оформления показывают выбранный способ; автоматическое включение СБП без настроек продавца исключено.
- Добавлен webhook ЮKassa `/api/payments/yookassa/notify`. Уведомление не подтверждает оплату само: сервер повторно запрашивает платёж по Merchant API и строго сверяет идентификаторы, RUB, сумму, статус и тип СБП.
- Платёжная сверка, фоновые проверки, события первой оплаты, отчёты, фильтр админки и диагностика дополнены методом `sbp`; повторные события не начисляют срок повторно.
- Контрактные тесты проверяют payload СБП, поддельные уведомления, повторные события, неверные суммы, способ оплаты и отмену. Реальный продавец/банк/webhook на VPS не тестировались.
- Подготовлены документация, установщик v0.054 и управляемое обновление с v0.053. Релиз публикуется только после CI.


## [0.053] — 2026-11-10

- Добавлен собственный редактор Telegram-меню: подписи, видимость, номер строки, две необязательные HTTPS-ссылки и локальный предпросмотр в кабинете владельца.
- Состояние хранится отдельно в SQLite, новые установки получают прежнее меню по умолчанию. Миграция идемпотентна и не перезаписывает изменения владельца.
- Валидация ограничивает набор системных действий, длину меток, ссылки и две кнопки в одной строке. Покупку нельзя скрыть; сохранение атомарное с проверкой версии и записью действий в штатный аудит.
- Бот использует актуальное меню при новом /start. Временная ссылка аккаунта создаётся только при отправке видимой кнопки; предпросмотр не создаёт билеты.
- Добавлены регрессионные тесты API, меню, прав и защиты от ошибочных настроек. Работа на реальном Telegram/VPS не подтверждена.
- Версия, установщик, диагностика и управляемое обновление подготовлены к v0.053, включая переход с v0.052. Выпуск тега — после CI.


## [0.052] — 2026-11-10

- Введён read-only API `/api/platforms`: web/Telegram — реализация в коде; VK/MAX/Matrix — исключительно план, без ложного статуса подключения. Авторизация разных платформ не объединяется автоматически.
- Уточнено разделение Shop VPN и самостоятельного MTProxy Pushok: исторические рекламные файлы сохраняются до планового извлечения, никакой общей БД/готовой интеграции нет.
- Незнакомый VPN-протокол отклоняется до проверки, выдачи и отзыва на внешнем сервере, вместо ошибочного маршрута в WireGuard.
- Добавлены проверки публичного API, конфиденциальности сведений и отказа для неподдерживаемых протоколов.
- RemnaShop однозначно закреплён только как референс для анализа меню, локализации, платёжных интерфейсов и архитектуры. Не добавлены зависимость, сервис, контейнер, интеграция или копии его исходников; составлен собственный план улучшений Shop VPN.
- Номер кода, установщика и диагностики обновлён до v0.052, поддержана подготовка управляемого обновления с v0.051. Проверки CI/VPS/реальных платежей пока не подтверждены.

## [0.050] — 2026-11-06

- Добавлены проверки меню, контекста, актуальных настроек, длины и маршрутизации polling. Обновлено управляемое обновление с v0.049.

- Недоступная история не подменяется нулевыми значениями; проверены устаревшие ответы и очистка после ошибки.

## [0.048] — 2026-11-06

- Отчёт использует когорту по времени создания заказа и текущие статусы; суммы показаны по валютам и не называются банковской выручкой или прибылью.

- Добавлены проверки регистрации владельца и нормализации адреса; управляемое обновление с v0.021–v0.045 закреплено за v0.046.

## [0.045] — 2026-11-06

- Добавлен серверный приём подписанных событий внешнего бота после подтверждённой оплаты услуги. Повтор с тем же ID идемпотентен; просроченная подпись, подмена события и недоступный промокод отклоняются.
- Партнёрский код доступен только Telegram-аккаунту из проверенного события. Право действует до 30 дней, соблюдает обычные лимиты купона и не передаёт данные клиента или панели внешнему боту.
- Настройки интеграции — отдельные PARTNER_PROMO_CODE и PARTNER_WEBHOOK_SECRET. Реальная доставка события из nail-studio-bot и покупка на VPS требуют отдельной приёмки.

## [0.044] — 2026-11-06

- Добавлен раздел владельца «Настройки магазина»: контакт поддержки и условия продажи редактируются без изменения `.env` и перезапуска.
- При первом запуске начальные значения импортируются из `.env` в базу; далее применяются версия записи и проверка конфликтующего редактирования.
- Новые значения сразу используются витриной, проверкой условий Telegram-оплаты/пробного доступа и командами бота `/support` и `/terms`.
- Исправлен выход владельца из админки: сессия и данные на экране очищаются сразу, запоздалые ответы не возвращают их.
- CI проверяет тесты магазина, интерфейса, обновление/восстановление Docker-данных и сценарий WireGuard. Установка на целевой VPS и проверка реальной панели не выполнялись.

## [0.043] — 2026-11-05

- Добавлен Bearer API-адаптер VLESS-панели с созданием и продлением пользователя, отзывом доступа и повторным чтением результата.
- Идентичность пользователя панели связана со стабильным UUID профиля; повтор после потерянного ответа ищет прежнюю запись и не должен создавать дубликат.
- Добавлена настройка токена и групп доступа в реестре серверов админки; профиль хранится зашифрованным.
- Обновляемая ссылка магазина для такого профиля перенаправляет клиента на актуальную ссылку подписки панели; в кабинете показан импорт подписки по URL.
- Добавлена read-only диагностика API-панели в `scripts/panel_check.py`; отчёт отдельно указывает, что права записи и ссылку подписки она не проверяет.
- Дополнен `docs/STAGING.md`: описана безопасная стендовая приёмка Remnawave API, потери ответа, повторов, продления, URL-подписки и фактического отзыва трафика. Все реальные шаги остаются невыполненными до отдельного стенда.
- Обновлены README и дорожная карта.
- Выпуск не опубликован: автоматические тесты и проверка на реальной панели не выполнялись. GitLab pipeline завершился до запуска задач (jobs: 0). Установщик по-прежнему закреплён на v0.038.

## [0.042] — 2026-11-05

- Добавлена CLI-проверка SMTP: без параметров она проверяет TLS, авторизацию и ответ сервера, не отправляя письмо.
- Опциональная тестовая отправка требует явного `--send-to`; секреты берутся из `.env` и не передаются в аргументах команды.
- Добавлен скрипт в Docker-образ и инструкции по проверке письма.

## [0.041] — 2026-11-05

- Добавлен безопасный запрос сброса пароля для email-аккаунта с одинаковым ответом независимо от наличия пользователя.
- Одноразовый токен хранится в базе только в виде хеша, действует 20 минут, передаётся через URL-фрагмент и погашается после использования.
- После смены пароля отзываются текущие веб-сессии и ссылки входа. Частые письма одному аккаунту ограничены.
- Добавлена отправка через SMTP с STARTTLS или SSL, без записи реквизитов и ссылок восстановления в журнал. Пустая SMTP-конфигурация отключает доставку.

## [0.040] — 2026-11-05

- В личном кабинете добавлены обращения в поддержку с темой, сообщением и необязательной привязкой к собственному заказу.
- Пользователь может открыть переписку, ответить на обращение и видеть его состояние. Повторное создание защищено ключом запроса; конфликтующие изменения обнаруживаются по версии.
- Сотрудники поддержки получают отдельную очередь обращений, могут ответить клиенту или закрыть обращение. Действия сотрудников проходят через существующий аудит.
- Email-уведомления и автоматический сброс пароля не включены: для этого нужна проверенная отправка почты. Пользователи Telegram могут открыть кабинет командой `/account`.

## [0.038] — 2026-11-05

- Добавлена административная сводка рекламы: учтённые поступления, полные возвраты, расходы и остаток после учтённых расходов за выбранный период. Остаток не объявляется чистой прибылью.
- Отдельно показаны оплаченные заявки на текущий момент: не запущены, активны, на паузе, остановлены с остатком и с подтверждённым полным сроком/остановкой. Истёкший таймер без остановки не считается завершённым размещением.
- Добавлен ручной журнал расходов по категориям с датой, ID документа и основанием. Ошибочную запись можно исключить с причиной; это коррекция учёта, а не возврат денег.
- UUID, уникальный ID действующего расхода и версии защищают от повторов. Сохраняются исходные записи и причины исправлений; журнал входит в зашифрованную копию.
- Сводка использует один снимок SQLite и времени, явные границы периода и пагинацию. Банковские записи считаются по времени их сохранения, расходы — по указанной владельцем дате; полнота данных не подтверждается автоматически.
- Обновлены ROADMAP и план MTProxy: отмечены версии v0.032–v0.038, ручные границы, отложенная приёмка VPS/узла/реальных платежей и следующие приоритеты. MTProxy остаётся дополнительным направлением магаз…7477 tokens truncated…значений.
- Наблюдение за циклами worker в памяти процесса: начало/успех/ошибка, предупреждения о долгом цикле и отсутствии свежего завершения; сброс при старте.
- Отдельные показатели сохранённых API-проверок серверов и полноты настроек без выдачи секретов, идентификаторов клиентов и текстов ошибок.
- Обновление/копирование JSON в админке, защита от запоздалых ответов и очистка при выходе.
- CLI status.py: только HTTP loopback, без proxy/редиректов и вывода тела ошибок; включён в Docker-образ.
- Отчёт не выполняет внешних запросов и не подтверждает VPN-трафик, реальные платежи или восстановление копий.
- Установщик закреплён на v0.023; --upgrade сохраняет только фиксированный переход v0.021 → v0.022. Реальная Docker/VPS-приёмка необходима.

## [0.022] — 2026-11-05

- Управляемый переход установщика v0.021 → v0.022: plan/prepare/status/activate/rollback, общий lock и постоянный журнал без секретов.
- Отдельный новый Docker volume и образ; старый том сохраняется, согласованная зашифрованная копия создаётся после остановки shop и проверяется после сохранения на хосте.
- Offline-проверка и init_db без сети; новая версия сначала запускается в режиме обслуживания без покупок, бота и worker.
- Явная активация после проверок; до неё возможен откат к прежнему immutable image ID и тому. После начала активации откат базы заблокирован.
- Проверки версий, исходников, конфигурации, действительного volume и контрольных сумм; при ошибке подготовки попытка возврата прежнего магазина.
- Повторный установщик не перезаписывает managed-upgrade; архивы и материалы обновления исключены из исходников/Git/Docker-контекста.
- Backup v0.022 читает совместимые архивы v0.021; установщик закреплён на v0.022. Реальный Docker/VPS-переход требует приёмки.

## [0.021] — 2026-11-05
