# Установка одной командой

Поддерживаются Ubuntu 22.04/24.04 LTS, amd64/arm64. Нужны домен с DNS на этот VPS,
доступ root либо sudo, curl, Python 3 и доступ в интернет. На стандартном Ubuntu
Python 3 уже установлен. Скрипт проверяет поддерживаемую ОС до установки магазина.

```bash
curl -fsSL https://raw.githubusercontent.com/mrkoster1988/Shop-VPN-/v0.028/install.sh | bash
```

Команда устанавливает фиксированную версию v0.028. Скрипт скачивает архив этого
же тега по HTTPS, проверяет пути/типы файлов и размер до распаковки. Вопросы читает
из терминала, поэтому запуск через pipe не мешает диалогу. При обычном пользователе
запрашивается sudo. Для просмотра действий без установки:

```bash
curl -fsSL https://raw.githubusercontent.com/mrkoster1988/Shop-VPN-/v0.028/install.sh | bash -s -- --plan
```

## Диалог и режимы

Установщик спросит адрес магазина (например https://pushok.shop/shop), внутренний
порт (обычно 8000), способ HTTPS и контакт поддержки. Токен Telegram можно ввести
скрыто или оставить пустым; тогда сайт доступен по email, бот подключается позднее.
При добавлении бота спрашиваются username и условия продажи. Токены не передаются
в аргументах команд и не печатаются. Настройка VPN-серверов выполняется через админку
после установки. VPN-панель, узлы и WG-интерфейс этот установщик не разворачивает.

| Режим | Когда выбирать | Что делает |
|---|---|---|
| `caddy` | Порты 80/443 свободны, нужен новый HTTPS-сайт | Запускает отдельный прокси с автоматическим сертификатом и постоянными volumes |
| `nginx` | Домен уже обслуживается Nginx, основной сайт нужно сохранить | В выбранный HTTPS server добавляет include маршрутов /shop; сохраняет прежние location |
| `external` | Другой прокси, сложная или контейнерная конфигурация | Запускает магазин на loopback и создаёт nginx.shop.conf для ручной интеграции |

Для нового HTTPS проверьте A и, если задана, AAAA запись, внешний доступ к 80/443
и отсутствие другого сервиса на этих портах. Установщик не меняет firewall и не
останавливает занявший порт процесс. Выберите другой внутренний порт, если 8000 занят.
В режиме caddy запросы вне магазина возвращают 404: этот режим для нового сайта.

Для Nginx укажите **файл конфигурации существующего HTTPS-сайта на хосте**, обычно
/etc/nginx/sites-enabled/ваш-сайт. Должен существовать ровно один server с нужным
server_name и listen 443 ssl в этом файле. Сертификат должен быть настроен заранее.
Перед правкой выполняется nginx -t, копия сохраняется в backups. После добавления
include — повторная проверка и reload; при отказе исходный файл восстанавливается.
Шаблоны ${...}, неоднозначные блоки и уже имеющиеся маршруты /shop автоматически
не переписываются: для них используйте external и включите маршруты самостоятельно.
Парсер не заменяет стендовую проверку вашей конкретной конфигурации Nginx.

Режим external заканчивается с кодом 2 и сообщением «HTTPS пока не подключён».
Это подготовленная установка, а не готовый публичный сайт. После подключения
прокси проверьте публичный /shop/health и вход. В Docker-прокси loopback относится
к контейнеру: настройте доступ к приватному/host адресу магазина по своей схеме.

## Результат

По умолчанию файлы находятся в /opt/pushok-vpn:

- `.env` (0600): ключ администратора, ключ шифрования и настройки.
- `source/`: исходники фиксированного релиза.
- `installer.json`: сохранённые параметры и постоянное имя Compose-проекта.
- `compose.install.json`: конфигурация запуска, совместимая с Docker Compose.
- `nginx.shop.conf`, `Caddyfile`, `backups/`: файлы прокси и его резервные копии.

Админка доступна по адресу магазина с /admin. Прочитайте ADMIN_TOKEN из .env локально
на сервере; не отправляйте файл в чат или Git. Изменять ENCRYPTION_KEY после выдачи
доступов без миграции нельзя. База хранится в постоянном Compose volume; TLS также
имеет отдельные volumes. Магазин слушает только 127.0.0.1, один процесс.

Если Docker уже установлен, используются его Engine и Compose v2. При отсутствии
Docker установщик добавляет официальный apt-репозиторий и устанавливает Engine с
Compose plugin. Конфликтующий контейнерный runtime не удаляется автоматически;
такой случай требует отдельной подготовки. При наличии Docker без рабочего Compose
или недоступном daemon установщик останавливается, сохраняя конфигурацию для повтора.

После установки добавьте серверы через админку, проверьте API, настройте условия,
поддержку и оплату. Отдельно проверьте настоящий VPN-трафик и покупку по STAGING.md.
Успешный health-check магазина не доказывает работу VPN или платёжного провайдера.

## Повтор, восстановление и ограничения

Повторите ту же команду: версия, URL, порт, режим, имя проекта, .env и volume
сохраняются. Это повтор/восстановление **той же установки**, а не автоматическое
обновление старой версии. В другой версии либо в непустом неуправляемом каталоге
установщик откажется от изменений. Ранее развёрнутый вручную магазин не переносится
молча: нужна отдельная миграция с резервной копией базы и исходных секретов.

Параллельный запуск блокируется. Ни docker compose down -v, ни удаление базы,
ни остановка чужих контейнеров не выполняются. При ошибке DNS, сертификата или
сборки сохранённые настройки остаются для исправления и повторного запуска.
Не публикуйте .env в выводе диагностических команд.

Управление (подставьте project из installer.json):

```bash
cd /opt/pushok-vpn
docker compose --project-name PROJECT --env-file .env -f compose.install.json ps
docker compose --project-name PROJECT --env-file .env -f compose.install.json logs --tail=100 shop
```

Для запуска без диалога можно задать URL, режим и поддержку; секреты генерируются,
бот остаётся ненастроенным. Для nginx также нужен --nginx-config:

```bash
curl -fsSL https://raw.githubusercontent.com/mrkoster1988/Shop-VPN-/v0.028/install.sh | bash -s -- --yes --url https://example.com/shop --mode caddy --support '@support'
```

При следующем релизе VERSION в install.sh и scripts/install.py должен совпадать с
новейшей версией CHANGELOG: это проверяется в тестах. Обновление существующих
инсталляций с резервным копированием/откатом будет отдельным этапом.


Шаблоны прокси дополнены защитой приватных /shop/sub/ URL. При ручном
обновлении существующего прокси включите эти правила до использования ссылок подписки.
Для Caddy 2.8+ log_skip исключает access log, фильтр default runtime log заменяет URI;
объедините global-настройки с существующими. Для Nginx отдельная location отключает
access и error log этого пути. Собственные CDN/APM/logging правила проверьте отдельно.


Резервные копии магазина, отдельный пароль, Docker и восстановление в новый каталог
описаны в [BACKUP.md](BACKUP.md). Не копируйте один shop.db у работающего SQLite вместо
согласованного снимка; сохраняйте .env и состояние VPN-узлов отдельно по инструкции.


Для установленных через установщик версий v0.021/v0.022/v0.023/v0.024/v0.025/v0.026/v0.027 доступно отдельное
обновление до v0.028, включая подтверждённый managed-upgrade. Обычный install.sh не
запускает обновление сам: используйте `--upgrade plan`, затем `--upgrade prepare`,
проверьте результат и выполните `--upgrade activate` либо `--upgrade rollback` до
начала активации. Команды, проверки текущего тома и ограничения: [UPGRADE.md](UPGRADE.md).

Незавершённые старые операции сначала закончите инструментом их целевого релиза.
Изменённые установки и более старые версии требуют отдельного плана. Bootstrap v0.028
использует фиксированный v0.028 для новой установки и обновления.

Локальный отчёт в админке и CLI нового образа: [DIAGNOSTICS.md](DIAGNOSTICS.md).
Он не подтверждает работу VPN-трафика, реальный платёж и восстановление копии.

Автоматическая проверка Docker lifecycle на одноразовом CI-runner: [DOCKER_STAGING.md](DOCKER_STAGING.md).
Она не заменяет установку и платёжную/VPN-приёмку на вашем VPS.
