# Подключение WGDashboard к Shop VPN

Адаптер включён в выдачу оплаченного заказа, продление и отзыв подписки.
Настройка доступна в кабинете владельца: **Серверы → Новый сервер → WireGuard →
WGDashboard**. Реальная панель и VPN-трафик пока не прошли приёмку.

## Настройка сервера

1. В WGDashboard включите API, создайте отдельный ключ и подготовьте активный
   WireGuard-интерфейс, например `wg0`. AmneziaWG этим адаптером не поддерживается.
2. В форме сервера укажите адрес панели **без `/api`**, API-ключ и точное имя
   интерфейса. При установке панели под префиксом включите его в адрес.
3. Сохраните профиль и нажмите «Проверить API». Проверка читает интерфейсы,
   но не создаёт peer и не подтверждает работу VPN-трафика или право записи.
4. Включайте приём новых заказов только после тестовой приёмки ниже.

Для изменения названия/локации оставьте профиль подключения пустым: сохранённые
секреты останутся в базе. Смена панели требует полного профиля. Для сервера с
подписками запрещена смена URL, типа API или интерфейса — добавьте другой сервер.
Pushok WG-агент остаётся отдельным пунктом выбора, автоматического переключения нет.

Профиль API реестра для автоматизации:

```json
{"protocol":"wg","settings":{"api":"wgdashboard","url":"https://dashboard.example/prefix","token":"YOUR_API_KEY_AT_LEAST_32_CHARACTERS","configuration":"wg0"}}
```

## Выдача, повтор и отзыв

До первого сетевого изменения магазин создаёт X25519-ключ и сохраняет его в
`wgdashboard_keys` с шифрованием штатным `ENCRYPTION_KEY`. Пара сервер/UUID
идентичности уникальна, создание сериализовано транзакцией SQLite. Повторная попытка,
перезапуск и продление используют прежний ключ; новое устройство получает свой.

По публичному ключу адаптер ищет peer до создания и проверяет результат после.
Ограниченный вручную peer автоматически не включается. Скачанный конфиг проверяется
на совпадение приватного ключа, адреса, endpoint, размер и разрешённые поля.
Исполняемые hooks из шаблона отклоняются, имя файла панели не используется.
Конфиг затем шифруется штатным сценарием выдачи магазина.

После удаления проверяется отсутствие peer в активном и ограниченном списках.
Ключ сохраняется для повторной сверки. При отсутствии сохранённого ключа отзыв
возвращает ошибку и не создаёт замену. Резервная копия должна содержать и базу,
и прежний `ENCRYPTION_KEY`; тест восстановления проверяет расшифровку того же ключа.

**Сейчас отключение по сроку выполняет worker магазина.** При остановленном магазине
или недоступной панели peer может оставаться активным после срока. Автономное
ограничение срока на стороне WGDashboard ещё не включено.

## Проверка без изменения клиентов

Создайте JSON-файл профиля (`url`, `token`, `configuration`, необязательно
`api: wgdashboard`) с правами 0600 от текущего пользователя:

```bash
chmod 600 /secure/wgdashboard.json
python scripts/panel_check.py --wgdashboard --profile-file /secure/wgdashboard.json --output /secure/wgdashboard-check.json
```

Отчёт создаётся без перезаписи, права 0600. Код 0 — контракт чтения подтверждён;
1 — ошибка API; 2 — ошибка локальных параметров. Проверяется TLS, редиректы и прокси
окружения отключены. Отчёт не содержит ключей, URL и тела ответа панели.
Доступность API не доказывает аутентификацию, если защита панели выключена.

## Приёмка

- Покупка: один peer, получен конфиг, импорт и VPN-трафик работают.
- Повтор после потерянного ответа: прежний ключ, второй peer не создан.
- Продление: прежний peer, срок заказа увеличен один раз.
- Дополнительное устройство и ротация: отдельная идентичность, старый peer отозван.
- Истечение: работающий worker удаляет peer; ошибка панели остаётся на повтор.
- Резервное копирование и восстановление: ключи сохранены и расшифровываются.

Контрактные тесты используют HTTP-фикстуры, тест заказа — имитацию адаптера.
Они не заменяют реальную панель, оплату и проверку VPN-трафика.

## Следующий этап: срок на стороне панели

Изучен `PeerScheduleJob` в исходниках WGDashboard. POST создаёт, PUT изменяет
задание по `JobID`; список заданий возвращается в `jobs` записи peer. Удаление
peer доступно как действие `delete`. `ExpireDate` означает завершённость задания,
а не срок подписки: условие времени задаётся через `Field`, `Operator` и `Value`.

Планировщик сравнивает `datetime.now()` панели со строкой без UTC-смещения.
Для реализации нужны явный часовой пояс панели, обработка переходов времени,
постоянная идентичность задания и подтверждение его сохранения перед выдачей.
Повторы/продление должны обновлять своё задание, а истечение, удаление peer и
перезапуск панели — не создавать конфликт с прежним завершённым заданием.
Проверка должна включать выключенный магазин при работающей панели.
