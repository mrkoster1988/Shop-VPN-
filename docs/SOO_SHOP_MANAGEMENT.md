# Управление puShok shop VPN — роли и настройки

## Вход

Адрес кабинета — PUBLIC_URL + /admin. При размещении Shop по адресу https://pushok.shop/shop это https://pushok.shop/shop/admin. Для установки на отдельном домене без префикса — https://ваш-домен/admin.

В пользовательском кабинете и внизу сайта добавлена ссылка «Вход для сотрудников». Она ведёт на отдельный вход, не выдаёт полномочия обычному пользователю. Нужны email и пароль сотрудника. При первоначальной настройке один раз применяется ADMIN_TOKEN, чтобы создать первого разработчика. Ключ установки не публикуется и не отправляется в Telegram. Pushok ID SSO для сотрудников — отдельный будущий этап, текущий клиентский токен не даёт административных прав.

## Роли

| Роль | Что доступно |
| --- | --- |
| Разработчик | Полный доступ, включая назначение сотрудников, матрицу прав, серверные ключи, настройки, обновления и финансовые действия. |
| Администратор | По умолчанию сводка, пользователи, заказы и повтор выдачи, тарифы, акции, пробный доступ, автовыдача WireGuard, просмотр состояния серверов, модерация, поддержка, настройки магазина, аналитика и диагностика. Разработчик включает или исключает группы. Подтверждение оплаты и редактор меню отключены по умолчанию. |
| Модератор | По умолчанию отдельная очередь заявок на рекламу с решением и причиной. Поддержку можно разрешить отдельно. Доступ к оплате, ключам, управлению сотрудниками и серверами не делегируется. |

Существующие оператор панелей, менеджер MTProxy, финансовый сотрудник и поддержка сохраняют прежние серверные права. Новые роли не получают их автоматически. Пользователь магазина не является сотрудником. Владелец прежних установок отображается как «Разработчик» (совместимый внутренний код owner).

## Настройка

1. Войти разработчиком. Верхняя навигация показывает доступные разделы.
2. «Сотрудники» — добавить администратора/модератора, назначить роль существующему сотруднику или отключить его. Назначение ещё одного разработчика требует явного подтверждения; последнего действующего разработчика и свою учётную запись нельзя понизить/отключить.
3. «Полномочия» — включить нужные группы для администратора/модератора, сохранить. Матрица использует версию; конфликт изменений отклоняется. Группа payments требует orders. Запрещённые права не принимаются даже прямым API.
4. «Модерация» — просмотр только необходимых полей заявки, одобрение/отклонение с причиной. Денежные операции и фактическое размещение отделены.
5. Остальные настройки магазина остаются в существующих разделах: тарифы, лимиты устройств, промокоды, бонусы, условия, пробный доступ, серверы, расписание обновлений, автовыдача.

## Миграции и безопасность

Добавляются две пустые таблицы: staff_role_assignments и staff_role_policies. Существующие идентификаторы и учётные записи не изменяются. У новых делегированных ролей базовая legacy-запись выключена, а актуальное назначение и состояние определяются таблицей назначений: старый бинарник не может выдать им права поддержки при откате. Устаревшие сеансы инвалидируются при смене роли или отключении сотрудника. Разрешения роли проверяются при каждом запросе. Уже принятый параллельный запрос может завершиться; обновление интерфейса перечитывает права.

Разработчик управляет матрицей ролей, а не произвольным кодом API. Неизвестные маршруты закрыты для новых ролей. Настройки ключей, установки, обновления и назначения разработчиков остаются защищены; пароли и серверные секреты не включаются в список сотрудников. Ведение аудита сохраняется.

Это первый блок административного управления. Отдельно предстоит расширить права до индивидуальных назначений, согласовать единый вход Pushok ID и перенос операционных настроек из окружения в защищённый интерфейс. Включение платежей, замена секретов и изменения работающей инфраструктуры выполняются только с безопасной процедурой проверки.
