# Pushok Shop — светлая админка и безопасное удаление данных

## Дизайн

- Только административная страница использует белый фон, светлые карточки, тёмный читаемый текст и ненавязчивые бирюзовые акценты.
- Мобильная версия сохраняет полноценный доступ к разделам и крупные области нажатия.
- Публичный магазин и Telegram Mini App не меняют тему.
- Исправлена некорректная HTML-разметка пункта «Ожидает оплаты» в фильтре заказов.

## Доступ

**Разработчик (owner)** может выполнять необратимые действия. Обычные администраторы, модераторы и операторы не могут вызвать API удаления даже вручную. В интерфейсе кнопки скрыты у прочих ролей.

## Подписки — карточка пользователя

Откройте «Пользователи» → карточку пользователя.

1. «Отозвать доступ» — Shop проверяет незавершённые заказы и ротацию ключей, пытается отозвать все известные первичные и дополнительные подключения у соответствующего провайдера. Доступ не отмечается отозванным до подтверждения панели. При ошибке сети/панели запись остаётся, действие можно повторить.
2. После подтверждённого отзыва блокируются личные ссылки, очищаются сохранённые конфигурации, отключается автопродление. История оплат остаётся неизменной.
3. «Удалить запись» — доступно только для ранее подтверждённого отзыва и только когда удаление не разрушает обязательную историю. Дополнительное текстовое подтверждение «УДАЛИТЬ».
4. Записи с `flow_auto_grants`, `referral_redemptions`, незавершёнными платежами или историей смены ключей **не удаляются физически**: их доступ можно отозвать, но сама запись сохраняется ради целостности и предотвращения повторного бесплатного получения.

Ни удаление, ни отзыв не обнуляют платежи, не стирают финансовые документы и не удаляют аккаунт пользователя.

## Тарифы

У выключенного пользовательского тарифа появляется «Удалить неиспользуемый тариф». Удаление запрещено для тарифов с заказами, ссылками из купонов и системных исходных тарифов (month, quarter, year). Такие тарифы можно скрыть от покупателя.

## Серверы

В карточке выключенного сервера без подписок появляется «Удалить пустой сервер». Backend также запрещает удаление, если остались WireGuard-ключи, задания срока, учётные записи протоколов или другие связанные данные. Живые серверы не удаляются этой функцией.

## Проверка и выпуск

Точки API (owner only):
- `POST /api/admin/subscriptions/{sid}/revoke`
- `DELETE /api/admin/subscriptions/{sid}`
- `DELETE /api/admin/plans/{plan_id}`
- `DELETE /api/admin/servers/{sid}`

Поддерживающие изменения: `app/admin_cleanup.py`, миграция `admin_subscription_revocations` в `app/db.py`, панели `app/static/admin.js` и `style.css`. Тесты: `tests/test_admin_cleanup.py`, `tests/test_admin_ui.cjs`.

Перед обновлением действующего VPS: создать и проверить резервную копию БД и ключа шифрования, выполнить CI и тест удаления на отдельном тестовом пользователе. Проверить, что пир действительно отсутствует в WGDashboard/3x-ui, и только затем использовать новую функцию с реальными подписками. Это изменение GitHub **не означает**, что интерфейс и миграция уже установлены на VPS.
