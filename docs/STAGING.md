# Стендовая приёмка Shop VPN

Эта процедура ещё не выполнена на реальной инфраструктуре. Используйте отдельный
стенд, тестовые учётные записи и резервные копии. Доступ к production не требуется.

## Состав

Магазин по /shop с отдельной SQLite, панель для Legacy, панель для Clients JSON,
WG-агент и клиентское устройство. Для каждого узла запишите версию установленного
ПО и выбранный режим API, не включая токены, конфиги и приватные ключи в отчёт.
Подготовьте один рабочий VLESS inbound на каждой панели. Не используйте чужие
клиентские записи в качестве тестовых.

## Последовательность

1. Запустите магазин с пустой базой. Добавьте три выключенных сервера в админке.
   Проверьте каждый API и включите приём. До успешной проверки включение должно
   давать отказ. Убедитесь, что реквизиты не возвращаются в ответах API магазина.
2. Оставьте активной первую панель. Зарегистрируйте покупателя, оформите заказ с
   ручной оплатой и подтвердите его после тестовой проверки. До подтверждения
   ключ не выдаётся. После выдачи сохраните локально UUID и время окончания.
3. Импортируйте конфиг на устройстве, проверьте доступ в интернет через туннель.
   Зафиксируйте время и результат проверки без публикации конфигурации.
4. Переведите первую панель в «только продления» и включите вторую. Продлите первого
   покупателя: сервер и UUID должны сохраниться, дни добавиться к прежнему сроку.
   Новый покупатель получает доступ через вторую панель.
5. На Clients JSON повторите покупку, импорт и продление. В самой панели проверьте
   единственную запись служебного email, UUID магазина и правильный inbound.
   Настройки существующего клиента должны сохраниться после продления.
6. Имитируйте потерю ответа после создания клиента на отдельном тестовом прокси.
   Перезапустите магазин и дождитесь повтора: второй ключ не создаётся, срок не
   начисляется повторно. Затем восстановите обычное соединение и проверьте трафик.
7. Задайте лимит одной подписки на пустом тестовом сервере. Новый клиент после
   заполнения места не должен назначаться на него, продление существующего доступно.
   Если пул заполнился после оплаты, заказ остаётся оплаченным в очереди.
8. Проверьте неверный токен, недоступный endpoint, редирект и неподходящий API.
   Ошибка не должна приводить к смене режима, ключа, сервера или раскрытию секретов.
   Восстановите профиль, проверьте API и повторите выдачу из админки.
9. Для WG проверьте импорт .conf, QR, интернет, продление с тем же ключом/IP и
   отзыв тестового peer после истечения срока.
10. Восстановите копию базы прежней версии с прежним .env: старые подписки получают
    исходную привязку. Повторный запуск с изменённым .env не переносит их.
    Без полного исходного профиля миграция должна откатиться и остановить запуск.
11. Восстановите базу и ключ шифрования из резервной копии. Проверьте вход,
    очередь, скачивание своего конфига и отсутствие доступа к чужим подпискам.

## Результат

Для каждого пункта сохраните дату, версии, ожидаемый/фактический результат и
идентификатор тестового заказа. Прикладывайте только очищенные логи. В отчёте
разделяйте доступность API и фактическое прохождение VPN-трафика. Непройденный пункт
остаётся блокером выпуска на сервер, даже если автоматические тесты проходят.


## Клиентский мастер подключения — v0.011

Проверьте на Android, iPhone/iPad, Windows, macOS и Linux выбор платформы,
копирование, ручное выделение при запрете clipboard, скачивание .conf/.txt и QR
со второго экрана. В Mini App отдельно проверьте разрешения на скачивание и буфер.
Закройте окно во время загрузки и выйдите из аккаунта с открытым QR: приватные
настройки не должны вернуться. Проверьте окончание срока и продление при открытом
мастере. Убедитесь, что «Продлить» выбирает исходный протокол. Основной профиль доступен отдельно; дополнительные профили проверяйте по разделу ниже.


## Устройства — v0.012

Для Legacy, Clients JSON и WG добавьте два дополнительных профиля. Убедитесь,
что ключи отличаются между собой и от основного; импортируйте их на разные устройства
и проверьте реальный интернет. Повторите запрос с тем же request_id: ключ один.
Продлите подписку, убедитесь в сохранении всех ключей и добавлении дней. Имитируйте
сбой после обновления одного профиля, перезапустите worker и проверьте повтор без
повторного начисления срока. Отзовите один профиль: его файл/QR недоступны сразу,
но отключение трафика подтверждайте после выполнения удалённой задачи. При отказе
сервера статус должен остаться «Отключаем доступ». Остальные устройства и основной
профиль должны работать. Проверьте четыре занятых слота, освобождение после отзыва,
окончание срока всех профилей и возобновление неотозванных после продления.
Проверьте свободные адреса WG и фактическую ёмкость сервера с дополнительными ключами.
