# Flow: доступ принадлежит аккаунту Pushok, без привязки телефона

## Проверяемая идентичность

Для `POST /shop/api/flow/bridge/exchange` нужен 60-секундный одноразовый
билет MTProxy, подтверждающий Telegram ID и его связь с Shop `user_id`.
Нельзя принимать ID, email или ник из произвольного запроса; сопоставление
личности, anti-replay, HMAC и HTTPS остаются обязательными.

Поле `client_id` **не участвует в авторизации**: новые Flow-клиенты вовсе
не посылают его; старые клиенты могут прислать прежнее поле, но оно
игнорируется. Старые строки `flow_bridge_devices` не удаляются миграцией
и больше не ограничивают аккаунт. Доступ к действующей подписке определяется
подтверждённым `shop_user_id`, правом доступа и сроком подписки.

**Без ограничений телефонов ≠ без срока или подтверждения оплаты.**
Первый бесплатный доступ по-прежнему зависит от включённой владельцем
политики, готового WGDashboard с безопасным API и фактического peer.
Повторный вход не начисляет второй бесплатный период, не создаёт лишние
платежи и не продлевает подписку молча.

## Управление доступом

**Удаление:** Pushok Flow удаляет персональную подписку только из локального
каталога, отключает автоматический повторный импорт и сохраняет аккаунт,
историю и серверное право. В Shop разработчик может отозвать подтверждённо
на WGDashboard сам peer; это отдельная операция. Удаление финансовой истории
и записей пробной выдачи запрещено — после отзыва их можно архивировать,
но не маскировать отсутствие аудита удалением БД.

**Продление:** обычная покупка/продление по тарифу Shop действует через
существующий заказ и подтверждение платежа. Для тестового доступа разработчик
имеет отдельное ручное продление:

- `GET /shop/api/admin/users/{user_id}/wireguard/extend/plan?days=30` —
  рассчитанный срок на исходной подписке;
- `POST /shop/api/admin/users/{user_id}/wireguard/extend` —
  подтверждение разработчика с UUID заявки и причиной (аудит).
  Сначала WGDashboard подтверждает новый scheduled expiry прежнего peer,
  только затем Shop увеличивает срок. При ошибке срок и права не меняются,
  повтор выполняется **с тем же UUID/датами**, без двойных дней.

Продление разрешено только для реально существующего WireGuard-ключа на
том же закреплённом WGDashboard; не перемещает сервер, не создаёт
платёж, не переписывает историю. Для истёкшего права при подтверждённом
восстановлении прежнего ключа тот же аккаунт получает актуальный документ
подписки.

## Мультиустройства: оговорка WireGuard

Вход и право принадлежат **аккаунту**, ограничение по телефону отсутствует.
Однако один WireGuard private key, импортированный одновременно на несколько
активных телефонов, может вызвать перехват последнего endpoint и обрывы
туннелей. Это техническое свойство WireGuard, не ограничение входа Pushok.
Для действительно одновременных независимых подключений следует создавать
отдельные peer/ключи для каждой активной сессии при общем аккаунте и
едином сроке доступа. Это дальнейшая серверная задача, не повод ограничивать
вход в аккаунт.

## Развёртывание

Сам коммит в GitHub **не обновляет VPS**. Перед активацией нужны зелёные
Python/Node, браузерные, Docker-upgrade, реальный WG-стенд и проверка
конкретной установки Shop. Публичный HTTP WGDashboard недопустим для
удалённого администратора Shop с API-ключом: нужен TLS или защищённый
частный канал. Проверяйте результат на физическом Android через
новую версию Flow.

Не публикуйте персональный URL подписки, `.conf` и ключи.
