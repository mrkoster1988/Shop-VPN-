# Проверка обновлений магазина

Владелец видит раздел **«Обновления магазина»** рядом с настройками в админке.
По умолчанию сервер проверяет стабильный релиз **ежедневно в 21:00 Europe/Moscow**.
Время, часовой пояс IANA и включение расписания сохраняются в базе. Открытый браузер
не нужен. При первом запуске выполняется начальная проверка; затем действует расписание.

## Что доступно

- Текущая версия сборки, опубликованный релиз и его описание.
- Последняя попытка, последняя успешная проверка и время следующего запуска.
- **«Проверить сейчас»** — запрос к GitHub; **«Обновить статус»** — чтение сохранённого результата.
- Редактирование расписания; **«Отменить изменения»** загружает сохранённые значения.
- **«Обновить»** при подтверждённой новой версии открывает порядок ручного обновления
  и `docs/UPGRADE.md`, закреплённый на теге этого релиза.

При подключённой [службе обновления на VPS](HOST_UPDATER.md) это окно показывает подготовку плана и отдельное подтверждение установки. Без службы сохраняется ручная инструкция. Само расписание не запускает установку. Кнопка доступна только владельцу; совместимость проверяется по реальной установке, а не только по номеру версии.

Служба использует [существующий обновлятор](UPGRADE.md): зашифрованную копию, отдельный том и проверку новой версии. После подтверждения владельца выполняются подготовка и активация. До активации возможен откат; после её начала возврат старой базы запрещён. VPN-панели и узлы не обновляются.

## Надёжность расписания

Проверка работает отдельной фоновой задачей, не внутри цикла платежей и выдачи доступа.
Период опроса расписания — 30 секунд: запуск около выбранной минуты, при работающем
сервере и доступном event loop. Пропущенная проверка выполняется после запуска сервера
один раз; очередь запросов за каждый пропущенный день не создаётся.

Если `BACKGROUND_TASKS=false` или `MAINTENANCE_MODE=true`, автоматическая проверка
не запускается. При выключенных фоновых задачах и работающей админке доступна ручная.
В режиме обслуживания админка тоже недоступна. Экран показывает, что расписание
приостановлено настройкой фоновых задач. Выключение расписания не отменяет уже начатую
проверку и не запрещает кнопку «Проверить сейчас».

Состояние, ETag, время следующей проверки и аренда выполняющегося запроса хранятся в
SQLite. Аренда истекает через 120 секунд; поздний ответ не заменит результат нового запроса.
Тайм-аут всей сетевой операции — 20 секунд. После ошибки повторы идут через 15 минут,
1 час, затем 6 часов; ограничения GitHub учитываются отдельно, до 24 часов.
Ручные запросы разрешены не чаще раза в минуту и соблюдают ограничения GitHub.
Повтор одного времени при переводе часов не создаёт второй ежедневный запуск;
несуществующее местное время при весеннем переводе сдвигается вперёд на величину разрыва.

При сбое прежний результат сохраняется с явным предупреждением. Данные старше 48 часов
считаются устаревшими; переход к обновлению скрывается до свежей успешной проверки.
Открытая страница владельца обновляет сохранённый статус примерно раз в минуту,
не отправляя каждый раз запрос в GitHub. Введённое, но не сохранённое расписание остаётся
в форме; параллельные изменения защищены версией. При конфликте загрузите сохранённое
через «Отменить изменения» и заново внесите правку.

## Источник и доступ

Источник фиксирован: публичный GitHub-репозиторий `mrkoster1988/Shop-VPN-`,
[`GET /repos/{owner}/{repo}/releases/latest`](https://docs.github.com/en/rest/releases/releases#get-the-latest-release).
Ветки main, отдельные коммиты, drafts и prereleases не предлагаются как обновление.
Проверяется формат тега проекта `vX.YYY`; версии сравниваются численно.
Описания показываются текстом, без исполнения HTML/Markdown. Ссылки строятся только
на наш репозиторий и подтверждённый тег; внешние URL из ответа не используются.

Запросы идут по HTTPS без редиректов и proxy из окружения, ответ ограничен 256 КиБ.
Ключи магазина/панелей и токен владельца не отправляются в GitHub. GitHub-токен не нужен.
Ошибки возвращаются фиксированными кодами без содержимого ответа внешнего сервиса.

Все три маршрута доступны только владельцу и входят в обычный аудит админки:

| Метод и путь | Действие |
|---|---|
| `GET /api/admin/updates` | Состояние, без внешнего запроса |
| `PUT /api/admin/updates/schedule` | Расписание с проверкой версии |
| `POST /api/admin/updates/check` | Ручная проверка с ограничением частоты |

На установке в `/shop` перед путями API добавляется `/shop`.
Настройки и результат входят в полную резервную копию базы. Миграция добавляет таблицу,
сохранённое расписание повторным запуском `init_db` не перезаписывается.

## Установка из админки

Служба, настройка, восстановление после прерывания и границы автоматических проверок описаны в [HOST_UPDATER.md](HOST_UPDATER.md). Код находится в Unreleased; в установленном v0.055 его ещё нет. Служба включается отдельно владельцем VPS. Веб-приложение не получает Docker socket или произвольные команды.
