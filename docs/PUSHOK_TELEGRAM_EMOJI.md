# Pushok Custom Emoji — подключение к Telegram Bot API

## Статус
Владелец подтвердил публикацию набора [PushokIcons](https://t.me/addemoji/PushokIcons) из **12 эмодзи** — [Issue #39](https://github.com/mrkoster1988/Shop-VPN-/issues/39). В репозитории есть загрузка набора, визуальная сверка и подготовка карты реальных ID. Получение ID с токеном целевого бота, его право на значки и приёмка настоящих клиентов ещё не подтверждены. **По умолчанию значки выключены.**

50 SVG/PNG веб-интерфейса и 12 опубликованных эмодзи — разные каталоги. Скрипт не предполагает, что порядок или картинки совпадают. Нативные кнопки Telegram не принимают SVG из веб-ассетов.

Первоисточник: https://core.telegram.org/bots/api#inlinekeyboardbutton и https://core.telegram.org/bots/api#keyboardbutton.

## 1. Получить ID и изображения

Из каталога исходников Shop, Python 3.10+ (внешние библиотеки не нужны):

```bash
python3 scripts/sync_pushok_emoji.py fetch --output data/pushokicons-review
```

Токен **тестового** бота вводится скрыто в локальном терминале. Если `BOT_TOKEN` уже передан процессу как секрет, используется он; `.env` автоматически не читается. Не передавайте токен аргументом команды, в переписке или GitHub. Без терминала и переменной команда завершается до обращения к сети.

Скрипт читает `getStickerSet(name=PushokIcons)`, проверяет тип `custom_emoji`, ровно 12 уникальных ID и принадлежность набору; через `getFile` получает статичные изображения/миниатюры. Создаёт новый каталог с правами `0700`:

- `inventory.json` — ID, обычный emoji, `file_id`, `file_unique_id`, хеши изображений и время получения;
- 12 изображений и `review.html` — локальная галерея с подписями и копируемыми ID;
- `mapping.json` — шесть действий с пустыми значениями `custom_emoji_id: null`.

Откройте `review.html` локально и заполните `mapping.json` по **изображениям**, сохраняя ID строками. Никакого автоматического назначения по номеру или обычному emoji нет. Если соответствующего изображения нет, оставьте `null`: кнопка будет работать с текстом.

| Действие | Значок в карте | Что сверять по изображению |
| --- | --- | --- |
| `buy` | `cart` | Покупка / корзина |
| `account` | `user` | Кабинет / пользователь |
| `support` | `support` | Помощь / поддержка |
| `terms` | `rules` | Документ / условия |
| `link1`, `link2` | `link` | Ссылка; допустим один общий ID |

Один ID для разных по смыслу значков отклоняется. Если набор изменился и в нём больше или меньше 12 элементов, команда останавливается: сначала нужно обновить согласованный состав, а не молча переназначать кнопки.

## 2. Проверить карту через Telegram

После визуальной сверки:

```bash
python3 scripts/sync_pushok_emoji.py prepare \
  --inventory data/pushokicons-review/inventory.json \
  --mapping data/pushokicons-review/mapping.json \
  --images-reviewed \
  --output data/pushokicons-verified
```

Повторно читается набор: изменение порядка допустимо, замена изображения или состава требует новой сверки. Все выбранные ID отдельно проверяются через `getCustomEmojiStickers`. Результат:

- `button-icons.json` — готовый объект `action → custom_emoji_id` для существующей настройки Shop;
- `bindings.json` — проверяемая карта `action → icon → custom_emoji_id`, принадлежность набору и время проверки. Права бота и приёмка клиентов в ней остаются `pending`/`false`.

Это проверка существования и принадлежности ID, **не проверка разрешения бота показывать значки**. Никакие сообщения, платежи, настройки Shop или VPS не изменяются. При отказе API/тайм-ауте результат не публикуется, частичный каталог удаляется. Повтор запускайте с новым выходным каталогом: существующий не перезаписывается.

Сетевой доступ ограничен HTTPS `api.telegram.org`, редиректы и прокси из окружения отключены; размер ответов и время ожидания ограничены. Тексты ошибок Telegram и URL с токеном не выводятся. Запросы автоматически не повторяются после HTTP 429. Токен в результатах отсутствует; `data/` исключён из Git.

## 3. Включить на тестовом боте и принять

Убедитесь, что у бота есть право использовать custom emoji на кнопках: дополнительные имена через Fragment **либо** владелец с действующим Premium для сообщений, отправляемых ботом напрямую в личные чаты, группы и супергруппы. Успешный `getStickerSet` такого права не подтверждает.

Получить одну строку JSON для локального `.env` (это публичные ID, не токен):

```bash
python3 -c 'import json; print(json.dumps(json.load(open("data/pushokicons-verified/button-icons.json")), separators=(",", ":")))'
```

В `.env` **тестовой установки** скопировать результат в `PUSHOK_BUTTON_EMOJI_JSON='…'` и поставить `PUSHOK_BUTTON_ICONS_ENABLED=1`. Пустые/непроверенные значения не включать.

Пересоздать сервис магазина, чтобы он прочитал изменённый `.env`: бот работает внутри процесса Shop. Для установки через мастер используйте каталог и Compose-файлы своей установки из [инструкции](INSTALL_QUICKSTART.md); примените `docker compose ... up -d --no-deps --force-recreate shop` с теми же аргументами `-f`/`--env-file`. Обычный `restart` не обновляет переменные контейнера. Для отключения вернуть `PUSHOK_BUTTON_ICONS_ENABLED=0` и снова пересоздать сервис.

Сначала проверить меню на тестовом боте. После проверки прав и всех трёх клиентов можно переносить карту в нужную среду; автоматического включения нет. Для другого бота повторите `prepare` с его токеном и отдельную проверку меню.

## Гарантии обратной совместимости
- По умолчанию иконки выключены, старые тексты, callback, URL, права, токены и бизнес-операции не меняются.
- Некорректный/пустой JSON и ID не попадают в ответ Telegram.
- Лишние ключи настроек игнорируются.
- Отсутствующие ID не скрывают кнопки; текст остаётся видимым.
- Если Telegram явно отклонил `sendMessage` (HTTP 400, `ok=false`, `error_code=400`), меню отправляется ещё один раз с теми же подписями и действиями, но без значков. Второй отказ завершает попытку. Тайм-аут, неоднозначный ответ, HTTP 429 и серверные ошибки не запускают такой повтор: результат отправки может быть неизвестен. Платёжные запросы эта логика не повторяет.
- Ни одна иконка не означает успешную оплату/активацию без серверного подтверждения.

## Настройка
Параметры:
- `PUSHOK_BUTTON_ICONS_ENABLED=0` — выключено (по умолчанию).
- `PUSHOK_BUTTON_EMOJI_JSON='{"buy":"<реальный_числовой_ID>"}'` — карта действий; заменяйте пример настоящими ID после публикации набора.

Не храните токены ботов или личные данные в JSON-карте; это лишь публичные числовые ID эмодзи.
