# Shop VPN: короткая инструкция установки

Это инструкция к текущему мастеру в исходниках. Приёмка на чистой Ubuntu и выпуск обновлённого однокомандного загрузчика ещё не завершены. `install.sh` пока скачивает фиксированный релиз v0.054, поэтому новые подсказки из main в него автоматически не попадут.

## Перед запуском

Нужны Ubuntu 24.04 (также поддерживается 22.04), доступ sudo и домен, направленный DNS-записью на сервер. Для существующего сервера сначала сохраните резервную копию конфигурации прокси. Панель на pushok.shop можно оставить на прежнем адресе, магазин разместить в /shop.

## Как установщик попадёт на VPS

Файл скачивается с GitHub непосредственно на сервер. Переносить его вручную с телефона или компьютера не нужно.

**Сейчас этот способ устанавливает закреплённый релиз v0.054, а не последние изменения main.** Обновлённая команда для следующего проверенного релиза будет опубликована после приёмки. Новые подсказки диалога пока доступны только в исходниках main.

1. Откройте SSH-клиент на телефоне или терминал компьютера и подключитесь к VPS:

   ```bash
   ssh USER@SERVER_IP
   ```

   Замените `USER` на имя пользователя сервера, а `SERVER_IP` — на IP из кабинета хостинга. Если уже открыта консоль VPS, подключаться повторно не нужно.

2. Все следующие команды выполняйте **в консоли VPS**. Сначала подготовьте Ubuntu.

   Если на сервере уже работает панель или VPN, сделайте снимок VPS в кабинете хостинга и выберите время для обслуживания: обновления могут перезапустить службы.

   Обновите список пакетов и установленные пакеты в пределах текущей версии Ubuntu:

   ```bash
   sudo apt-get update
   sudo apt-get upgrade
   ```

   Просмотрите список изменений и подтвердите установку. Если появится вопрос о замене изменённого конфигурационного файла, не заменяйте его вслепую: сохраните текущий файл, если не знаете, зачем нужна новая версия. Переход на другую версию Ubuntu для установки магазина не требуется.

   Установите компоненты для загрузчика:

   ```bash
   sudo apt-get install -y curl python3 ca-certificates
   ```

   Проверьте, требуется ли перезагрузка:

   ```bash
   if [ -f /var/run/reboot-required ]; then
     cat /var/run/reboot-required
   else
     echo 'Система не сообщает о необходимости перезагрузки'
   fi
   ```

   Если перезагрузка требуется и окно обслуживания согласовано, выполните `sudo reboot`. SSH-соединение закроется. Дождитесь запуска VPS, снова подключитесь командой из шага 1 и проверьте работу уже установленной панели/VPN, затем продолжайте шаг 3. Установщик магазина сам систему не обновляет и сервер не перезагружает.

3. Скачайте установщик в отдельный каталог:

   ```bash
   mkdir -p ~/pushok-setup
   cd ~/pushok-setup
   curl --fail --location --proto '=https' --proto-redir '=https' https://raw.githubusercontent.com/mrkoster1988/Shop-VPN-/main/install.sh -o install.sh
   ```

   После успешной загрузки файл `install.sh` находится на VPS в каталоге `~/pushok-setup`. Если curl сообщил об ошибке, сначала устраните её и повторите скачивание.

4. Посмотрите план без установки:

   ```bash
   bash install.sh --plan
   ```

   Загрузчик скачает исходники закреплённого релиза во временный каталог. Мастер спросит основные параметры и покажет план, не устанавливая компоненты.

5. Для установки указанного выше релиза запустите диалог:

   ```bash
   sudo bash install.sh
   ```

   Повторно ответьте на вопросы по таблице ниже: режим `--plan` не сохраняет ответы. Магазин по умолчанию разместится в `/opt/pushok-vpn`. Файл `~/pushok-setup/install.sh` — только загрузчик; исходники релиза он получает сам.

Если вошли под `root`, `sudo` перед командами не требуется. Для уже установленного магазина используйте процедуру обновления, а не новую установку.

## Для разработки: запуск из полученных исходников

В каталоге проекта сначала посмотрите план:

```bash
python3 scripts/install.py --plan
```

План не устанавливает компоненты и не запрашивает токен. На Ubuntu мастер предложит основные параметры. Для установки запустите:

```bash
sudo python3 scripts/install.py
```

## Что отвечать

| Вопрос | Ответ и подсказка |
|---|---|
| Адрес магазина | `https://pushok.shop/shop` — замените домен на свой. Путь `/shop` обязателен в текущем мастере. |
| Режим | `caddy` для свободных 80/443; `nginx` для существующего HTTPS Nginx; `external` для работающего Caddy или другого прокси. |
| Внутренний порт | Enter = `8000`. Если занят, повторите запуск с `--port 8001`. |
| Файл HTTPS-сайта Nginx | Только в режиме nginx: полный путь к действующему файлу с вашим `server_name` и HTTPS. Не угадывайте путь. |
| Контакт поддержки | Например `Telegram: @your_support`. Будет показан покупателям. |
| Токен бота | Получите у @BotFather через `/newbot`. Ввод скрыт. Enter = подключить позже. |
| Имя бота | Имя созданного бота без `@`, например `your_shop_bot`. |
| Условия продажи | Ваши реальные условия. Можно заполнить позже перед включением продаж. |

Enter принимает значение в скобках. Ctrl+C прерывает работу; если установка уже началась, созданные файлы могут остаться. Повтор с теми же параметрами поддерживается для незавершённой установки текущей версии. Для обновлений используйте отдельный механизм upgrade, не новую установку поверх данных.

## Драйверы и компоненты: что действительно нужно

- **Сам магазин:** отдельные драйверы, графическая среда и GPU не нужны. Используется ядро и оборудование, предоставленные VPS.
- **Docker и Compose v2:** установщик проверяет существующий Docker; при его отсутствии устанавливает Docker Engine, Compose и Buildx. Если найдена конфликтующая контейнерная среда или неработающий Docker, потребуется исправить её отдельно. Работающие контейнеры не удаляются ради установки.
- **Python-зависимости приложения:** устанавливаются при сборке контейнера. Вручную ставить FastAPI, базу данных или библиотеки в систему VPS не нужно.
- **Подключение к удалённой 3x-ui, Remnawave или WGDashboard:** на VPS магазина VPN-драйвер не нужен — магазин обращается к API панели.
- **WireGuard-узел на этом же VPS:** это отдельный этап. Нужны поддержка WireGuard ядром, сетевые настройки и доступ виртуализации к нужным функциям. Не устанавливайте случайные драйверы или DKMS-пакеты заранее; требования узла проверяются при его настройке. Для LXC/OpenVZ ограничения может потребоваться снять у хостера.

## Что установится

Docker/Compose при необходимости, приложение Shop, база и настройки, Telegram-бот при заданном токене, фоновая обработка заказов. В режиме caddy — HTTPS-прокси. В режиме nginx — подключение маршрута магазина с проверкой конфигурации и резервной копией изменяемого файла. В режиме external мастер создаёт пример маршрутов, но публичный HTTPS нужно подключить вручную; код завершения 2 означает этот незавершённый шаг.

## После установки

1. Откройте адрес магазина и `/admin` после него: например `https://pushok.shop/shop/admin`.
2. Ключ входа `ADMIN_TOKEN` находится в `/opt/pushok-vpn/.env`. Просматривайте файл только в своей SSH-сессии; не отправляйте его содержимое другим.
3. В админке добавьте сервер: 3x-ui, Remnawave, WGDashboard или WireGuard-агент. Для новых 3x-ui и WGDashboard добавлен отдельный мастер в исходниках: [установка и настройка панелей](PANELS_SETUP.md). В загрузчик v0.054 он ещё не входит.
4. Настройте тарифы, поддержку, условия и платежи. Изначально веб-оплата ручная; СБП и Stars требуют отдельной настройки. См. [СБП](SBP_PAYMENTS.md).
5. Для Telegram настройте HTTPS-адрес Mini App в @BotFather, затем проверьте вход, заказ, оплату и получение VPN-настроек.

Проверка доступности: `https://pushok.shop/shop/health`. Ответ `status: ok` подтверждает работу приложения, но не платежей и VPN. До продаж нужны пробная оплата, реальное подключение, продление и восстановление резервной копии.

## Если мастер остановился

- **80/443 заняты:** выберите nginx или external. Не отключайте работающую панель ради установки.
- **Внутренний порт занят:** выберите свободный через `--port`.
- **Не прошла проверка HTTPS:** проверьте DNS, сертификат и маршруты прокси; сохранённая конфигурация остаётся для диагностики.
- **Каталог не пуст:** не удаляйте данные. Используйте другой отдельный каталог через `--dir` либо штатное обновление существующего магазина.
