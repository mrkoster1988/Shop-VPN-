# Отдельные подписки WireGuard для устройств

Платный тариф использует существующую очередь устройств, лимит дополнительных профилей, отдельный credential_id и отдельный peer WGDashboard. Основной профиль сохраняется. Дополнительная подписка выдаёт только конфигурацию выбранного устройства, без ключей основного профиля или соседних устройств.

## Клиентский сценарий

Личный кабинет → Устройства → Открыть в Pushok Flow → Создать ссылку → Открыть в Pushok Flow. Передача HTTPS-ссылки производится через существующую страницу с fragment; подключение требует действия пользователя. Название устройства в кабинете задаёт владелец. Лимит — число профилей, не криптографическая привязка к конкретному физическому телефону.

## Контракт

- GET/PUT /api/flow/wireguard/devices/{did}/link: управление только владельцем по Shop session, CAS version, enable/rotate/disable.
- GET /api/flow/wireguard/devices/{did}: документ v1 для владельца.
- GET /flow/wireguard/device/{token}: персональный секретный HTTPS-адрес, не содержит административных прав.
- Стабильный profiles[0].id равен device id. revision повышается при изменении состояния, срока или конфигурации; повторное чтение неизменного документа не повышает revision. Продление сохраняет URL и профиль.
- pending/rotating/revoking: HTTP 409, не подтверждённое завершение. После подтверждённого отзыва peer — revoked и пустой profiles. Истечение срока — expired.
- Перевыпуск ключа отключает старый URL до удалённой операции. Повтор завершённого запроса не отзывает новую ссылку. Замена/отключение URL сами по себе не отзывают ранее скачанный ключ.
- Отдельные таблицы мигрируют без автоматических выдач. Хэш токена и зашифрованное значение хранятся отдельно. Резервное копирование проверяет шифрование. Восстановление старого архива отключает device URLs; штатное управляемое обновление из проверенного остановленного источника сохраняет их.
- Старые ревизии из архива не считаются подтверждённым текущим состоянием удалённой панели. После аварийного восстановления требуются проверка WGDashboard, повторная выдача ссылок и при необходимости отзыв ключей.
- Пробный профиль без дополнительных устройств и существующие VLESS/основные WireGuard-подписки не меняются.

## Приёмка

Backend: раздельные профили, продление, отзыв, повтор ротации, ограничения владельца, ошибки, backup. Frontend: выбор устройства, отсутствие утечки ссылки в запрос страницы, очистка при отзыве/закрытии. Затем CI, проверка Android Flow на реальном WGDashboard и отдельная приёмка с двумя устройствами. Автоматическая привязка отдельного read-сеанса Flow к device ID остаётся следующим этапом; этот PR не меняет MTProxy или Pushok ID.
