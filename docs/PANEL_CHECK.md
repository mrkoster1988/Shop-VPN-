# Предварительная проверка API VLESS — v0.030

Инструмент `scripts/panel_check.py` входит в образ магазина. Он вызывает выбранный
адаптер API: для Legacy — вход и чтение inbound, для Clients — чтение inbound и
проверку схемы списка. Записи клиентов не создаются, не изменяются и не удаляются.
Вход Legacy может создавать сессию авторизации на стороне панели.

## Профиль из существующего магазина

Выберите ID VLESS-сервера в админке своего стендового магазина. Подставьте имя
его контейнера и ID; значения ниже — примеры переменных, не реальные учётные данные.

```bash
SHOP_CONTAINER=имя_контейнера_магазина
SERVER_ID=идентификатор_сервера_из_админки
docker exec "$SHOP_CONTAINER" python scripts/panel_check.py --server "$SERVER_ID"
```

Профиль расшифровывается ключом текущего контейнера. SQLite открывается `mode=ro`:
отсутствующая база не создаётся. Health/state/version сервера не меняются; инструмент
не включает продажи и не изменяет подписки. Для WG-сервера эта проверка отклоняется.

## Профиль из приватного JSON

Создайте файл вне репозитория под текущим пользователем, установите права 0600.
Формат соответствует полю settings в API реестра сервера:

- Legacy: `api`, `url`, `username`, `password`, `inbound_id`, `link_template`, `flow`.
- Clients: `api`, `url`, `token`, `inbound_id`, `link_template`, `flow`.

`api` — `legacy` либо `clients`, `link_template` начинается с `vless://{uuid}@`.
Для публичного адреса нужен HTTPS. HTTP разрешён валидатором только для частной сети.
Приватный файл не должен быть симлинком; размер ограничен 16 KiB. Не публикуйте его
в GitHub/GitLab и не передавайте учётные данные в аргументах командной строки.

Из полного каталога исходников с установленными requirements.txt:

```bash
.venv/bin/python scripts/panel_check.py \
  --profile-file /root/private-panel.json --output /root/panel-api-report.json
```

Для контейнера можно передать профиль через stdin, сохранив файл только на хосте:

```bash
docker exec -i "$SHOP_CONTAINER" python scripts/panel_check.py \
  --profile-stdin < /root/private-panel.json
```

Для собственного центра сертификации укажите `--ca-file /path/to/ca.pem`. В контейнере
этот публичный CA-файл должен быть доступен его пользователю. TLS-проверка остаётся
включённой; режима `verify=false` нет. Редиректы не выполняются, прокси окружения не
используются. Тайм-аут отдельного HTTP-запроса — 20 секунд.

## Результат

| Exit code | status | Значение |
| --- | --- | --- |
| 0 | api_checks_ok | Авторизация/чтение VLESS, поддерживаемая схема и явно возвращённый ID inbound подтверждены |
| 1 | needs_attention | Панель недоступна, отказала, вернула redirect/неподдерживаемую схему либо не подтвердила ID |
| 2 | invalid_input | Профиль/локальный файл/CA/реестр/путь отчёта отклонён |

Отсутствующий ID не подменяется предположением по URL: `InboundIdentityNotReturned`
требует ручной проверки совместимости. Ошибки представлены фиксированными кодами,
без URL, токенов, паролей, UUID/email клиентов и тел ответа панели. Неизвестные причины
не выводятся через traceback. `checks` заполняются консервативно: при ошибке адаптера
инструмент не утверждает, какие промежуточные проверки были успешны.

`--output` создаёт JSON 0600 без перезаписи; stdout содержит тот же безопасный отчёт.
Файл отчёта уже существует — инструмент отказывает до обращения к панели.

## Граница приёмки

`api_checks_ok` — только чтение API. Оно не подтверждает подключение физического
клиента, правильность публичного endpoint/сертификата VPN, трафик VLESS, выдачу заказа,
продление, ротацию, отзыв, платёж, DNS/ACME или установку VPS.

Автоматические проверки инструмента используют контролируемые HTTP-ответы и настоящий
локальный HTTPS с тестовым CA. Docker-smoke читает зашифрованный профиль с закрытым
loopback-портом и проверяет безопасный отказ/сохранность базы. Удалённая панель этими
проверками не заменяется. Следующий шаг — подключить отдельный стенд и выполнить
последовательность из STAGING.md; этот этап пока не завершён.
