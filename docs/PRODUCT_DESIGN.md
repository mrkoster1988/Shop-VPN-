# Собственные продуктовые решения Shop VPN

Обновлено 12 ноября 2026. Анализ открытых реализаций использован для выбора задач; чужие исходники, интерфейсные ресурсы и программные стеки в Shop не переносились.

## Независимость

- Собственные аккаунты, каталог, заказы, платежи, бонусный учёт и интерфейс Pushok.
- Панели подключаются через адаптеры; ни одна из них не задаёт всю архитектуру магазина.
- В расчётах сохраняются целые денежные единицы и отдельные валюты RUB/XTR. Суммы не переводятся между валютами автоматически.
- Для операции различаются «запрос принят», «платёж подтверждён», «доступ выдан» и «проверен реальный VPN».
- Идея становится функцией только после собственной реализации и проверок. Перечень возможностей в чужом README не подтверждает работу его кода.

## Выбранные улучшения

| Направление | Что уже есть в Shop | Следующий собственный шаг | Критерий готовности |
|---|---|---|---|
| Первичная настройка | Диалог установки, проверка API, редактирование настроек | Единый мастер в кабинете: домен → бот → панель → тариф → оплата → тестовая выдача; сохранение завершённых шагов | После перезапуска продолжает с нужного шага; показывает причину сбоя; секреты не попадают в ответы |
| Сверка платежей | Проверка провайдера по webhook и фоновый polling | Видимый журнал сверки с причиной ожидания, последней проверкой и управляемым повтором | Потерянное уведомление не теряет оплату; повтор не удваивает доступ; сумма и валюта сверяются |
| Платёжные модули | Stars, ЮKassa, СБП и ручной сценарий | Отдельный контракт create/check/refund и описание доступности/лимитов каждого способа | Ненастроенный способ скрыт и запрещён на сервере; результат зависит от проверенного ответа провайдера |
| Расчёт цены и промокоды | Общий расчёт и снимок условий в заказе | Предварительная цена без создания заказа; проверка минимальной суммы у выбранного способа; резерв купона с освобождением | Повтор нажатия возвращает подходящий заказ; изменение суммы требует нового подтверждения; отмена освобождает резерв |
| Подключение и устройства | QR, файлы, ссылки, профили устройств | Один понятный экран «Подключить» с инструкцией по ОС и альтернативой при отказе deep link | Покупатель подключается без помощи администратора; QR и приватные настройки очищаются при выходе |
| Управление услугой | Тарифы и лимиты устройств | Отдельные предложения для новых/действующих клиентов; дополнительные устройства/трафик только при поддержке адаптера | Цена, срок и лимит воспроизводимы; неподдерживаемая возможность не продаётся |
| Эксплуатация | backup/restore, upgrade/rollback, статус | Кабинет диагностики с временем последней успешной копии и последнего проверенного восстановления | Бэкап проверен восстановлением; ключи не раскрываются; ошибку нельзя выдать за успех |
| Бренд и тексты | Русские тексты, редактор меню, настройки поддержки | Собственный каталог локализации, темы Pushok и предпросмотр изменений | Одна правка применяется согласованно в боте и кабинете, без копирования чужих баннеров/маскотов |
| Баланс и бонусы | Реферальные дни | Отдельный модуль общего кошелька и бонусов после стабилизации оплат | Атомарные резервы/списания/возвраты; повтор события не меняет остаток дважды; XTR отдельно |

## Что не переносим автоматически

- Платёжные заглушки, которые возвращают успешную проверку без обращения к провайдеру.
- Управление всей VPS из покупательского Mini App, выдачу SSH-ключей клиенту или автоматическую смену SSH-порта.
- Отправку резервных копий с пользовательскими данными в чат по умолчанию.
- Автоматическую смену базы, платёжного метода или API панели после неудачного запроса.
- Общий баланс без журнала операций, полномочий и проверенного сценария возврата.

## Порядок работ

1. Закрыть найденные блокеры CI, обновления и восстановления; проверить установщик и выпустить актуальный архив.
2. Проверить полный цикл оплаты и выдачи на одной реальной панели, затем на остальных.
3. Добавить мастер настройки и журнал сверки в админке — это снижает количество ручных команд и обращений в поддержку.
4. Доработать жизненный цикл промокодов/купонов, возвраты и платёжные адаптеры.
5. Развивать кошелёк, дополнительные предложения и оформление после стабилизации основной продажи.
