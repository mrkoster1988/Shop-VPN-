# Подключение панелей и замена ключей

[← Проверка API](PANEL_CHECK.md) · [Установка Shop](INSTALL_QUICKSTART.md) · [Протоколы](PROTOCOLS.md)

Функции этого этапа доступны в `main` после v0.055. Установочный архив v0.055
ещё не содержит пошаговую форму и отдельную замену доступа.

## Добавить подключение

Откройте админку магазина (при пути `/shop` это `/shop/admin`) под владельцем
или оператором панелей. В разделе **Серверы** нажмите **Добавить сервер**.

1. **Сервер**: название, локация, протокол и лимит подписок. Поля обязательных
   значений проверяются до перехода дальше.
2. **Подключение**: адрес управления и данные выбранной панели. Для 3x-ui
   Legacy нужны логин/пароль, для остальных API — токен. Дополнительно укажите
   inbound, группы или интерфейс и параметры протокола. Сначала настройте
   соответствующий inbound в самой панели; мастер его не создаёт.
3. **Проверка данных**: сводка названия, протокола, локации и лимита.
   Секреты и приватный адрес панели в ней не показываются. Кнопка **Назад**
   позволяет исправить поля, сохранив введённые значения.

После **Сохранить сервер** новый профиль остаётся выключенным. В его карточке
нажмите **Проверить API**, проверьте реальное VPN-подключение в клиенте, затем
выберите **Принимать новых** и сохраните настройки. Успешная проверка API не
подтверждает скорость, трафик, платежи или доступность всех узлов.

При редактировании профиля можно оставить весь блок подключения пустым, чтобы
сохранить прежний профиль. Для замены заполните блок целиком. Адрес и параметры
привязанного к подпискам подключения нельзя переназначить другому серверу.

## Обновить токен или пароль

В карточке сервера нажмите **Обновить доступ**. Это отдельная форма: адрес,
inbound, группы, интерфейс и клиентские конфигурации заново вводить не нужно.

- **3x-ui Legacy**: новый логин, новый пароль или оба значения. Пустое поле
  сохраняет прежнее значение; нельзя отправить оба поля пустыми.
- **3x-ui Clients, Remnawave, WG-агент, WGDashboard, S-UI**: новый API-токен.
- Сначала создайте токен или измените пароль в самой панели. Эта форма
  меняет сохранённый доступ магазина, а не пароль администратора внешней панели.

После сохранения Shop приостанавливает назначения и продления на этом сервере,
сбрасывает результат прежней проверки API и увеличивает версию профиля.
Нажмите **Проверить API**, затем верните нужный режим — **Принимать новых** или
**Только продления**. Действие не отзывает уже выданные VPN-конфигурации;
истечение подписок продолжает обрабатываться через настроенный адаптер.

При конфликте версии обновите список и откройте форму заново. Если соединение
оборвалось во время сохранения, сначала обновите список: операция могла успеть
выполниться. Автоматического повторного включения выдачи нет.

## Что защищено

Профиль хранится зашифрованным. API возвращает только публичные сведения о
сервере, а форма не подставляет сохранённые секреты. Поля нового доступа
очищаются при закрытии окна, успешном сохранении и выходе из админки.
Аудит фиксирует операцию без нового ключа или пароля. Финансовая роль,
поддержка и менеджер MTProxy менять эти данные не могут.

Замена выполняется одной транзакцией с проверкой версии. Проверка API,
начатая со старым ключом, не может пометить новый профиль исправным.
Привязки подписок, настройки WGDashboard и параметры VPN сохраняются.

## Границы этапа

Мастер использует существующие поддержанные адаптеры. NX пока имеет только
[отдельную диагностику](NX_PANEL.md); включения NX в эту форму и продажи нет.
Панель и протокол пока хранятся одним профилем сервера. Общая запись панели для
нескольких протоколов и загрузка inbound/шаблонов списком остаются в плане.
Приёмка реальных внешних панелей и трафика проводится отдельно от UI-тестов.
