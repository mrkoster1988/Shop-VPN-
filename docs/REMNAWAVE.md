# Подключение Remnawave v3 к Shop VPN

Shop VPN подключается непосредственно к панели Remnawave по REST API.
RemnaShop не требуется. Реализация рассчитана на контракт API v3.4.7;
совместимость более старой панели должна проверяться отдельно, автоматического
переключения на UUID API v2 нет.

Официальные источники, изученные 11 ноября 2026:
- API: https://docs.rw/api/
- Первоначальная настройка: https://docs.rw/learn-en/quick-start/
- Внутренние и внешние группы: https://docs.rw/learn-en/squads/
- Исходники backend: https://github.com/remnawave/backend/tree/9a51c76af9e20536d3faca74cf1b938fee32ab3c/src/modules/users

## Настройка

1. В Remnawave подготовьте рабочие ноды, хосты и внутреннюю группу доступа
   с нужными inbound. Проверьте тестовую подписку в VPN-клиенте.
2. В разделе настроек Remnawave → API Tokens создайте отдельный токен для магазина.
   Ему нужны права чтения пользователей, создания, обновления и отключения.
   Токен не публикуйте в чате, ссылках или скриншотах.
3. В кабинете владельца Shop VPN откройте серверы, добавьте сервер типа VLESS,
   выберите «Remnawave v3 · Bearer-токен».
4. Укажите HTTPS-адрес панели **без `/api`**, токен и UUID внутренних групп
   доступа (по одному в строке или через запятую). Это не UUID внешней группы,
   не UUID ноды и не ID inbound. Не заполняйте логин/пароль и шаблон VLESS.
5. Сохраните профиль. Нажмите «Проверить API». Эта проверка читает список
   пользователей и не создаёт тестового клиента. Она подтверждает доступ на чтение,
   но не права записи, работу нод или трафик.
6. После успешной проверки включите сервер. Для первой приёмки используйте
   отдельный тестовый тариф/аккаунт и проверьте весь сценарий ниже.

Токен и профиль хранятся зашифрованными; API админки не возвращает их обратно.
При редактировании оставьте весь профиль пустым для сохранения прежних настроек.
У сервера с подписками нельзя менять endpoint или набор групп: создайте другой сервер.

## Поведение магазина

Магазин создаёт отдельного пользователя с постоянным именем на основе UUID ключа
подписки и передаёт `vlessUuid`. При повторе сначала ищет того же пользователя.
Продление обновляет срок и статус, сохраняя остальные поля пользователя.
После записи проверяются имя, VLESS UUID, числовой ID, срок, ACTIVE, назначенные
группы и HTTPS-ссылка подписки. При несовпадении заказ остаётся на повторной выдаче.
Отключение использует числовой ID API v3 и подтверждается повторным чтением
именно этого пользователя. Ограничение срока передаётся в панель через `expireAt`.

Пустой список групп допускается для совместимости прежнего профиля, но не означает
доступ к нодам. Для рабочих продаж явно задайте правильные внутренние группы.
Webhook панели для базовой выдачи не требуется: операции инициирует магазин,
результат подтверждается чтением API. События панели и синхронизация ручных изменений
в обе стороны этим адаптером не реализованы.

## Приёмка

- Покупка: заказ оплачен, создан ровно один пользователь, назначены группы,
  ссылка открывается и импортируется, VPN-трафик проходит.
- Продление: прежние имя/UUID и ссылка, срок увеличен один раз при повторах.
- Ошибка/потерянный ответ: повтор не создаёт второго пользователя.
- Отключение: нужный пользователь DISABLED, соединение перестаёт работать.
- Истечение срока: панель ограничивает доступ по expireAt.
- Дополнительное устройство/ротация: отдельная идентичность, прежняя отозвана.

Автоматические тесты используют HTTP-фикстуры. Реальная панель, платежи,
импорт подписки и VPN-трафик должны пройти отдельную приёмку на вашем стенде.
