# TUIC v5 через S-UI

В v0.055 добавлены покупка, trial, промокоды, выдача `tuic://`, QR/файла,
продление, устройства, перевыпуск и отзыв через S-UI apiv2. Проверки кода и CI
отделены от приёмки реального клиента и VPS: она ещё не проведена.
S-UI устанавливается отдельно; магазин обращается к её API.

## Первый вариант поддержки

| Параметр | Условие |
|---|---|
| Аутентификация | TUIC v5: UUID и отдельный случайный пароль |
| Сервер | Включённый inbound `tuic` в S-UI, работающий core |
| Транспорт | UDP/QUIC, один публичный порт, проверяемый TLS |
| ALPN | `h3` в обоих TLS-профилях панели и в ссылке |
| Управление перегрузкой | `cubic`, `new_reno` или `bbr`; совпадает с inbound |
| UDP в клиенте | `native` либо `quic`, явно указан в ссылке |
| Отключены в этом этапе | 0-RTT, UDP-over-stream, ECH, mTLS, обфускация и insecure TLS |

TUIC v4 с токеном не поддерживается. Обновляемый URL подписки магазина пока
предназначен только для VLESS. Импорт TUIC-ссылки зависит от приложения:
поддержку TUIC v5 и параметров ссылки нужно подтвердить на выбранной версии.

## Настройка владельцем

1. Создайте и вручную проверьте TUIC inbound в S-UI. Откройте его UDP-порт.
2. В TLS-объекте включите серверный и клиентский TLS, задайте SNI и доверенный
   сертификат. В обоих профилях укажите `alpn: ["h3"]`; `insecure` оставьте false.
3. Выберите алгоритм `cubic`, `new_reno` или `bbr`; выключите `zero_rtt_handshake`.
4. Создайте API-токен S-UI. В магазине добавьте сервер **TUIC v5 · S-UI**.
5. Укажите адрес панели вместе с её путём (`https://panel.example/app`, без
   `/apiv2`), токен, inbound ID, публичный адрес VPN, порт, SNI и алгоритм.
   Режим UDP `native/quic` относится к клиенту и записывается в выдаваемую ссылку.
6. Сохраните выключенный сервер, проверьте API, затем включите назначения.
   API-проверка не проверяет доступность UDP и сертификат публичного VPN-порта.

Пример `settings` API магазина:

```json
{
  "api": "sui",
  "url": "https://panel.example/app",
  "token": "REPLACE_WITH_YOUR_SUI_API_TOKEN_32_CHARS_MINIMUM",
  "inbound_id": 7,
  "address": "vpn.example",
  "port": 443,
  "sni": "vpn.example",
  "congestion_control": "cubic",
  "udp_relay_mode": "native"
}
```

При наличии привязанных подписок нельзя менять endpoint, inbound или параметры
подключения сервера. Для другой конфигурации добавьте отдельный сервер.
API-токен можно заменить с повторной проверкой. Пустой профиль при редактировании
сохраняет прежние настройки; для смены режимов заполните его полностью.

## Повторы, пароли и отзыв

Пароль создаётся до запроса к панели и хранится зашифрованным в `tuic_credentials`.
UUID сам по себе не позволяет подключиться. Потеря ответа и повторная выдача
используют прежнюю пару; устройство и перевыпуск получают новую. Таблица
Hysteria2 и её существующие пароли не меняются.

Общая логика S-UI проверяет имя, единственный inbound, UUID, пароль, включение,
срок и политику клиента после записи. Продление не сбрасывает счётчики и лимиты.
Отзыв сохраняет `enable=false`, закрывает сессии и проверяет их отсутствие.
Ошибка оставляет задание для повтора. Изменившийся транспорт не мешает записать
запрет доступа. При остановленном core завершение отзыва ждёт его восстановления.
Подробности общих ограничений панели: [Hysteria2/S-UI](HYSTERIA2.md).

## Приёмка перед продажами

Запишите версию S-UI и клиента, ОС, алгоритм и режим UDP. Подтвердите покупку и
trial, импорт ссылки/QR, трафик через нужный узел, продление без второго клиента,
устройства и перевыпуск. После отзыва проверьте прекращение уже открытой QUIC-сессии
и отказ повторному подключению. Повторите с потерей ответа API, перезапуском магазина
и восстановлением копии. Проверяйте каждый используемый режим отдельно.

Нужны резервные копии базы и ключа шифрования магазина, а также отдельная копия
S-UI. Локальные тесты используют подменённый API; сетевой результат ими не подтверждён.
