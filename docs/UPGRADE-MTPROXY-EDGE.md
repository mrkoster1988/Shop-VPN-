# Обновление Shop рядом с MTProxy без installer.json

Действует для **существующей установки** `/opt/pushok-shop` с контейнером
`pushok-shop`, Compose-проектом `pushok-shop`, образом
`pushok-shop:mtproxy-edge` и постоянным томом `pushok_shop_data`.
Установки `/opt/pushok-vpn`, управляемые официальным мастером, по-прежнему
обновляются через [UPGRADE.md](UPGRADE.md); **не смешивайте процедуры**.

## Почему нужен отдельный режим

Соседство Shop и MTProxy использует `compose.mtproxy-edge.yaml` и, если
настроен WGDashboard по IP, локальный `compose.wg-ip.yaml`. Последний файл
не публикуется в GitHub и должен оставаться неизменным.
Штатному `scripts/upgrade.py` нужны `installer.json` и
`compose.install.json`, которых в этой схеме нет.

**Не создавайте фиктивные метаданные установщика, не запускайте
`install.sh` поверх каталога и не выполняйте `docker compose down -v`.**

Обновлятор для этой схемы — `scripts/upgrade_mtproxy_edge.py`.
Он *не* меняет Caddy, MTProxy, Pushok ID, WGDashboard, DNS или WireGuard-пиры.
Не используется основной `compose.yaml` (host network, занятый порт 8000).

## 1. Проверить VPS без изменений

```bash
cd /opt/pushok-shop
git status --short
git pull --ff-only origin main
python3 scripts/upgrade_mtproxy_edge.py plan \
  --dir /opt/pushok-shop --release v0.068
```

`git pull --ff-only` меняет отслеживаемые исходники, но не перезапускает
контейнеры, не заменяет `.env` и локальный `compose.wg-ip.yaml`.
Если Git сообщает о конфликте локальных изменений, **остановитесь**.
Не применяйте `git reset --hard`, `git clean -fd` или принудительную
замену Compose. Работающий Shop продолжает использовать прежний образ.

`plan` читает:
- эффективный Compose-конфиг (ровно один сервис `shop`);
- метки действующего контейнера и точный перечень Compose-файлов;
- образ, именованный том `pushok_shop_data` и права `.env`;
- состояние Docker health, внутренние `/shop/health` и `/shop/api/version`.

Выводятся только служебные сведения и контрольные суммы, а не `.env`
или токены. Если проверка прервана, не обходите ограничения: пришлите
только текст ошибки без приватных конфигураций.

## 2. Сохранить внешний бэкап и обновить Shop

Нужны рабочий root-терминал и свободное место на диске для Docker image,
зашифрованной копии (до 180 MiB) и временной распаковки релиза.
Открывайте сеанс `tmux`, если мобильное соединение SSH нестабильно.

До операции отдельно сохраните конфигурацию Caddy, локальный
`compose.wg-ip.yaml`, настройки WGDashboard и текущий snapshot VPS через
панель провайдера. Это не заменяет копию базы Shop.

```bash
cd /opt/pushok-shop
sudo python3 scripts/upgrade_mtproxy_edge.py apply \
  --dir /opt/pushok-shop \
  --release v0.068 \
  --confirm-edge-upgrade
```

Программа дважды запросит **отдельный пароль резервной копии** от 16 символов.
Сохраните пароль вне VPS. Для неинтерактивного запуска допускается
`--password-file /root/pushok-backup-password` (обычный файл 0600);
не передавайте пароль в аргументе или публичном чате.

Механизм выполняет следующие шаги **последовательно**:

1. Разрешает официальный стабильный релиз в SHA коммита, ограниченно
   скачивает исходники, собирает **отдельный** новый image, пока Shop работает.
2. Повторно проверяет ID контейнера, image, том, конфигурацию и SHA файлов
   `.env` и двух Compose. Любое изменение прекращает операцию.
3. Внутри **старого** контейнера создаёт зашифрованный SQLite Backup API
   snapshot, включая WAL и `.env`, проверяет расшифровку и целостность,
   копирует архив на хост, сравнивает SHA-256 перенесённого файла.
4. Сохраняет прежний образ с уникальным Docker-тегом. Помечает новый образ
   тегом `pushok-shop:mtproxy-edge`, выполняет Compose `up` **только**
   для `shop` с `--no-deps --no-build --force-recreate`.
5. Ожидает Docker health и проверяет, что в новом контейнере остался
   исходный том, появился целевой `/shop/api/version` и запущен
   собранный image. Результат и фазы фиксируются в закрытом журнале.

Том `pushok_shop_data` **не заменяется** и не восстанавливается из
архива поверх работающей БД. Устройства, аккаунты и ссылки WireGuard не
сбрасываются намеренно. `backup.pvb` сохраняется в приватном каталоге
`/opt/pushok-shop/edge-upgrades/<operation>/` (0700/0600), его нужно
перенести в собственное защищённое внешнее хранилище. Секретный пароль
нужен для аварийного восстановления.

## 3. Проверить состояние

```bash
cd /opt/pushok-shop
python3 scripts/upgrade_mtproxy_edge.py status --dir /opt/pushok-shop
docker inspect pushok-shop --format '{{.State.Health.Status}}'
curl --fail --silent --show-error https://pushok.shop/shop/health
curl --fail --silent --show-error https://pushok.shop/shop/api/version
```

После успешного обновления `/shop/api/version` должен вернуть `v0.068`.
Проверка health не заменяет тест выдачи нового пира в WGDashboard,
работы WireGuard, входа через Telegram, продления, отзыва и платежей.

## Если обновление прервалось

- `failed_before_switch`: контейнер Shop не должен был переключаться;
  проверьте фактический `docker inspect` и журнал перед новой попыткой.
- `recovery_required`: тег image или контейнер могли уже переключиться.
  Повторный запуск **заблокирован** до ручной диагностики.
- `complete`: сервис обновлён; не удаляйте старый образ, зашифрованную
  копию и журнал, пока не проверены реальные подписки.

**Никакого автоматического отката базы после переключения.**
Новая версия могла получить оплату, изменить состояние пира или
сделать миграцию SQLite. Механический возврат старой базы потеряет
такие события. Восстановление выполняют отдельно после сверки новых
платежей, заказов и состояния VPN-узлов. Для аварии пригодятся сохранённый
старый Docker image ID/rollback tag и архив `backup.pvb`.

## Ограничения

Инструмент специально отказывает, если Compose-файлы или имя тома
отличаются, контейнер unhealthy, `.env` открыт для посторонних,
присутствуют другие сервисы либо уже есть незавершённое обновление.
Он не устраняет проблемы реального WGDashboard, отсутствующих пиров,
сетевых ключей и API панели. Они проверяются отдельно.

Отправка кода на GitHub и зелёный CI **не означают**, что код уже
установлен на конкретном VPS. Серверная проверка и наблюдение
реального WireGuard после обновления обязательны.
