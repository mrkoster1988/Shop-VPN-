# Hysteria2 через S-UI

В текущем `main` магазин поддерживает Hysteria2 через **S-UI apiv2**: покупку,
trial, промокоды, выдачу ссылки/QR/файла, продление, профили устройств, перевыпуск
пароля и отзыв. Реальный клиент и целевой VPS ещё требуют приёмки.
Установщик v0.054 этот код пока не содержит и S-UI автоматически не устанавливает.

## Первый поддерживаемый вариант

| Параметр | Поддержка |
|---|---|
| Управление | S-UI apiv2, токен в заголовке `Token` |
| Inbound | Один включённый `hysteria2` на профиль сервера |
| Соединение | Прямой UDP/QUIC, один публичный порт, TLS с доверенным сертификатом |
| Обфускация | Без неё либо Salamander с точно совпадающим паролем |
| Выдача | `hysteria2://`, QR, текстовый файл; IPv4, IPv6 или DNS-адрес |
| Срок | Абсолютное время окончания, без delayStart и autoReset |
| Не входят в этап | Hysteria v1, нативный HTTP-auth сервера Hysteria, Realms, hopping, ECH, mTLS, Gecko и отключение проверки TLS |

URL обновляемой подписки магазина пока относится только к VLESS. Для Hysteria2
импортируется прямая ссылка доступа. Проверка API не доказывает доступность UDP,
корректность сертификата VPN-узла или работу приложения на телефоне.

## Настройка

1. Подготовьте отдельную S-UI с совместимым apiv2. Создайте включённый inbound
   Hysteria2 и проверьте подключение вручную. Панель управляет VPN-узлом; магазин
   остаётся самостоятельным приложением и собственной базой продаж.
2. Настройте TLS-объект inbound: `server.enabled=true`, `client.enabled=true`,
   одинаковое `server_name` с будущим SNI, `client.insecure=false`.
   Для первого этапа используйте обычный TLS без дополнительных режимов;
   ALPN оставьте пустым либо `h3`.
3. Если нужен Salamander, задайте его в inbound. Пароль магазина должен совпадать
   точно; допускается 16–256 символов без пробелов. Это общий параметр узла,
   отдельный от личного пароля подключения и API-токена панели.
4. Создайте API-токен в панели. В магазине откройте «Серверы» → **Hysteria2 · S-UI**.
5. Укажите адрес API с путём панели, например `https://panel.example/app`, без
   `/apiv2`. Затем токен, inbound ID, публичный адрес VPN, UDP-порт, SNI и пароль
   Salamander, если он включён. Адрес/порт VPN могут отличаться от адреса панели.
6. Сохраните сервер, выполните проверку API, затем включите новые назначения.
   Новый сервер создаётся выключенным. Проверка требует подходящего inbound,
   TLS, доступного списка клиентов и работающего ядра вне режима maintenance.
7. Оформите тестовую подписку и выполните приёмку ниже. Не включайте массовые
   продажи по одному успешному ответу API.

Пример поля `settings` при создании сервера через API магазина:

```json
{
  "api": "sui",
  "url": "https://panel.example/app",
  "token": "REPLACE_WITH_YOUR_SUI_API_TOKEN_32_CHARS_MINIMUM",
  "inbound_id": 7,
  "address": "vpn.example",
  "port": 443,
  "sni": "vpn.example",
  "obfs_password": ""
}
```

Ротация API-токена требует повторной проверки, но не меняет пароли покупателей.
Endpoint, inbound, адрес, порт, SNI и Salamander нельзя менять у сервера, к которому
уже привязаны подписки: для другого подключения добавьте отдельный сервер.
Пустой профиль при редактировании сохраняет старые зашифрованные настройки.

## Выдача, повторы и отключение

Для каждого профиля магазин создаёт отдельный случайный пароль и до сетевого
запроса сохраняет его зашифрованным в `hysteria2_credentials`. Идентификатор
подписки не используется как пароль. При потере ответа, перезапуске или продлении
повтор берёт прежний пароль; дополнительные устройства и перевыпуск получают новые.
Сохраняйте вместе базу магазина и её ключ шифрования: они нужны для управления
уже созданными клиентами. Миграция добавляет пустую таблицу, не меняя прежние записи.

Магазин ищет стабильное имя `pushok_<UUID>` в списке клиентов, затем отдельно читает
полный профиль по числовому ID. Запись выполняется через `/apiv2/save` только для
одного клиента. Проверяются имя, пароль и единственная привязка к inbound; чужая
или совместно используемая запись не перезаписывается. После записи повторно
проверяются идентичность, включение, точный срок, политика, TLS и состояние ядра.

При продлении сохраняются лимит трафика, заметки и счётчики. В зафиксированном
контракте S-UI нулевые `up/down` означают сброс; адаптер использует предусмотренную
ветку сохранения актуальных счётчиков. Исчерпанный лимит не сбрасывается покупкой:
такая выдача остаётся ошибкой до решения владельцем. Новые клиенты создаются без
лимита трафика; ограничения скорости и трафика не являются функцией этого этапа.

Отзыв сначала сохраняет `enable=false`, затем вызывает закрытие сессий клиента и
проверяет их отсутствие. Потеря ответа или оставшаяся сессия оставляют задание для
повтора. Изменившиеся TLS/Salamander и выключенный inbound не мешают записи запрета.
Если ядро остановлено, запись запрета сохраняется, а завершение отзыва ждёт успешной
проверки после восстановления ядра. Даже для удалённой записи клиента выполняется
закрытие прежних сессий. Обновление старой версии S-UI может быть необходимо для
отключения самих QUIC-сессий; совместимость со всеми версиями не заявляется.

## Приёмка на реальном сервере

1. Записать версию/коммит S-UI, версию клиента, ОС, TLS, UDP-порт и режим Salamander.
2. Купить тестовый доступ, импортировать ссылку целиком и подтвердить трафик через
   нужный узел. Не отключать проверку сертификата для устранения ошибки подключения.
3. Проверить trial, продление без второго клиента и повтор после потери ответа API.
4. Создать дополнительное устройство и перевыпустить основной пароль: проверить
   независимость профилей и отказ старому паролю после завершения отзыва.
5. Оставить QUIC-сессию открытой, завершить срок подписки и подтвердить прекращение
   трафика, а также невозможность повторного подключения.
6. Повторить с временно недоступной панелью, перезапуском магазина и восстановлением
   резервной копии. Проверить сохранение пароля и повтор очереди отключения.

Локальные тесты используют подменённый API и не заменяют эти проверки. Отдельно
проверяются реальные резервная копия/восстановление базы и сохранение секретов.
