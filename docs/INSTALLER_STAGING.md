# Проверка установщика на Ubuntu 24.04

[Установка магазина](INSTALL_QUICKSTART.md) · [Визуальный каталог](TECHNOLOGIES.md) · [Приёмка VPN и платежей](STAGING.md)

В CI добавлена job `installer-staging` на `ubuntu-24.04`. Она запускает неизменённый
`scripts/install.py` отдельным процессом из архива текущего коммита. Docker Engine
и Compose уже установлены на runner. Результат учитывается по конкретному запуску
[CI](https://github.com/mrkoster1988/Shop-VPN-/actions/workflows/ci.yml).

## Что проверяется

1. `--plan` не создаёт каталог, контейнеры и тома. Занятый порт и чужой непустой
   каталог приводят к отказу до установки.
2. Первая установка `--mode external`: настоящая сборка образа, Compose, миграция
   базы, health-check, loopback-порт, права файлов и постоянный том.
3. Код выхода **2** сопровождается сообщением «HTTPS пока не подключён».
   Это ожидаемая подготовка к подключению внешнего прокси.
4. Через локальный HTTPS-прокси стенда проверяются `/shop`, админка, диагностика,
   регистрация, cookie с Secure/HttpOnly и отказ запросу с чужим Origin.
5. После остановки контейнера повторная установка возвращает магазин в работу,
   сохраняя ключи, параметры, клиента, действующую сессию и том данных.
6. Попытка сменить порт существующей установки отклоняется без остановки магазина.
7. Очистка удаляет только ресурсы собственного тестового Compose-проекта.

JSON-отчёт печатается в лог job без ключей и cookie. В нём отдельно указаны точный
коммит, версия, завершённые проверки и результат очистки. Неуспех проверки либо
очистки делает job красной.

## Границы проверки

Это **первая установка Shop на Ubuntu с готовым Docker**. Она не подтверждает
установку Docker через apt на чистой ОС, публичный DNS/ACME, режимы Caddy/Nginx,
интерактивный диалог, установку дополнительных панелей, Telegram, платежи или VPN-трафик.
Локальный HTTPS использует отдельный доверенный тестовый сертификат; проверка TLS
не отключается. Архив кандидата создаётся через `git archive`; скачивание опубликованного
релиза загрузчиком сюда не входит.

Стенд запускается автоматически в CI и перед релизом. Ручной запуск допускается
только на отдельной одноразовой Ubuntu 24.04 с Docker, Compose, Git, OpenSSL и свободным
портом 443; нужен `--disposable`. На рабочем VPS этот тест не запускайте.
