# Партнёрские ссылки и гибкие настройки

Каждая установка магазина использует свой PUBLIC_URL, базу, секреты и правила продаж.
Внешний бот может показывать кнопку со ссылкой на магазин и предложением скидки.
Фактическую цену рассчитывает магазин; подпись кнопки во внешнем боте не является
правом изменить цену или подтвердить оплату.

## Что настраивается сейчас

| Настройка | Где задаётся |
| --- | --- |
| Домен и подпуть магазина | Установщик / PUBLIC_URL конкретной установки |
| Контакт поддержки, условия продажи | SUPPORT_TEXT / TERMS_TEXT текущей установки |
| Тарифы, цена, дни и лимит профилей | Админка магазина |
| Промокод, процент, срок, лимит применений, тариф и протокол | Админка промокодов |
| Пробный доступ и реферальные бонусы | Соответствующие разделы админки |
| Адреса и профили API VPN-серверов | Реестр серверов в админке |
| Кнопка, рекламный текст и URL предложения | Настройки внешнего бота |

Домен и часть параметров окружения задаются при развёртывании, а правила тарифов и
промокодов редактируются в админке. Единый кабинет всех настроек, брендинг и роли
сотрудников остаются следующими этапами; наличие переменной окружения не означает,
что она уже редактируется через веб-интерфейс.

## Обычная ссылка на скидку

1. Создайте в магазине промокод, например PARTNER15, задайте 15%, срок, лимит,
   подходящие тарифы/протоколы и включите его. Код и процент выбирает владелец.
2. В конфигурации внешнего бота укажите собственный домен магазина. Для схемы
   настроек VPN_PROMO_* пример выглядит так:

```dotenv
VPN_PROMO_ENABLED=1
VPN_PROMO_URL=https://example.com/shop/?promo=PARTNER15
VPN_PROMO_DISCOUNT_PCT=15
VPN_PROTOCOLS=VLESS,WireGuard
```

Замените example.com своим доменом. VPN_PROMO_DISCOUNT_PCT — рекламная подпись,
её нужно поддерживать в соответствии с фактическим промокодом магазина. Срок,
лимит и область действия проверяются на стороне магазина при расчёте.

3. Посетитель открывает обычную веб-ссылку, входит в магазин и выбирает тариф.
   Код подставляется в поле, но не применяется автоматически. Покупатель нажимает
   «Применить», видит рассчитанную сервером цену и подтверждает оформление.
4. При истёкшем/выключенном коде оформление с ним отклоняется. Покупатель может
   убрать код и заново выбрать покупку без скидки. Процент/цена из параметров URL
   не принимаются. Повторные применения ограничиваются существующими правилами купона.

При цене 199 ₽ и скидке 15% расчёт в целых единицах даёт скидку 29 ₽ и оплату 170 ₽.
Согласованные условия сохраняются в заказе; последующая смена процента не меняет его.

Код должен содержать 4–32 символа A–Z, 0–9, `_` или `-`, начинаться с буквы/цифры.
Регистр нормализуется. Повторные параметры promo и небезопасные значения игнорируются.
URL не запускает оплату, не создаёт заказ и не активирует пробный доступ.
Публичный код сохраняется до входа, а при выходе/ручном отказе от него очищается.

## Границы интеграции

Это обычная ссылка на сайт. Она не переносит автоматически Telegram-авторизацию
между разными ботами и не является отдельным маршрутом start/startapp. Вход магазина
и его собственный Telegram-бот настраиваются отдельно.

Общую ссылку можно переслать. Она не доказывает завершённый визит, оплату услуги,
статус клиента другого бизнеса или право на персональную скидку. Если предложение
должно выдаваться только по подтверждённому событию, нужен отдельный серверный обмен:
проверка подписи, короткий срок, уникальный ID события, разовое использование и журнал
повторов. Эта часть пока не реализована.

Текущая связь не передаёт записи клиентов и историю посещений в магазин. Внешнему
боту не выдаётся ADMIN_TOKEN, доступ к VPN-панелям или право подтверждать платежи.
Чужую базу магазин напрямую не читает. Репозиторий внешнего бота этим изменением
не модифицировался; для включения кнопки владелец задаёт его конфигурацию отдельно.

## Подписанное событие после подтверждённой покупки — v0.045

Обычную ссылку можно переслать, поэтому она подходит только для открытого предложения.
Для скидки после оплаченной услуги во внешнем боте создайте отдельный купон магазина,
например PARTNER15, и задайте в приватном .env:

```dotenv
PARTNER_PROMO_CODE=PARTNER15
PARTNER_WEBHOOK_SECRET=<случайный секрет не короче 32 символов>
```

Не используйте этот код в открытых рекламных ссылках. Когда он указан как
PARTNER_PROMO_CODE, магазин требует персональное право из подписанного события.
Процент, срок, тариф и лимит задаются обычными настройками купона в магазине.
Секрет храните только в .env с правами 0600 и передайте тому же партнёрскому боту
через защищённый канал. Не помещайте секрет, Telegram ID или реальные события в чат.

### Контракт запроса

Внешний бот отправляет событие только после своего подтверждения оплаты услуги.
Магазин не проверяет этот платёж и доверяет настроенному партнёру, владеющему секретом.

```http
POST /shop/api/partner/events
Content-Type: application/json
X-Partner-Timestamp: 1793900000
X-Partner-Signature: sha256=<HMAC-SHA256>
```

Подписываются точные байты тела вместе с Unix-временем:

```text
HMAC_SHA256(secret, timestamp + "." + raw_body)
```

Тело:

```json
{"event_id":"7ef315da-c2e1-4aeb-a879-5fdf1af4180b","telegram_id":123456789,"event_type":"service_purchase_paid"}
```

event_id — уникальный UUID оплаченного события. Повтор идентичного запроса идемпотентен;
тот же ID с изменёнными данными отклоняется. Подпись принимается с окном в пять минут.
Тело ограничено 4 KiB. Ответ не раскрывает, зарегистрирован ли Telegram ID в магазине.

Право действует 30 дней или до более раннего окончания купона. Сохраняются UUID события,
Telegram ID, код купона, хеш нормализованных данных и времена получения/окончания.
Записи ID события сохраняются для защиты от повторной выдачи; право на скидку истекает отдельно.
История салона, услуги и платежи партнёра в магазин не передаются.

Покупатель входит тем же Telegram-аккаунтом, который использовал у партнёра, вводит
код и нажимает «Применить». Сервер проверяет право и стандартные ограничения купона.
Создание заказа расходует купон обычной транзакцией; второй заказ по нему невозможен.
Другие купоны и email-аккаунты продолжают работать по прежним правилам.

### Проверки перед включением

1. На отдельном стенде включите уникальный PARTNER_PROMO_CODE и случайный секрет.
2. Отправьте тестовое событие; проверьте повтор, другой Telegram ID, просроченную подпись
   и изменённый payload с тем же event_id.
3. Войдите соответствующим Telegram-аккаунтом, примените код и проверьте сумму заказа.
   Другой аккаунт и email-вход не должны получать эту скидку.
4. Выключите купон или исчерпайте лимит: новые события должны отклоняться.
5. Подключите тестовый внешний бот и подтвердите, что он отправляет событие только после
   фактического подтверждения своей тестовой оплаты.

Этот выпуск описывает API магазина; внешний бот не изменён. Реальный обмен и платёж
пока не проверялись на сервере.
