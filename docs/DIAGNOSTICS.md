# Локальная диагностика — v0.023

В админке `/shop/admin` появился раздел «Состояние магазина». Отчёт можно обновить
кнопкой и скопировать из поля JSON. `GET /api/admin/diagnostics` требует ADMIN_TOKEN,
не делает внешних запросов и не изменяет настройки, состояния заданий или доступы.
Ответ имеет `Cache-Control: no-store`; при выходе содержимое отчёта очищается.

## Что показывает отчёт

- Очереди выдачи/продления, сверки ЮKassa, создания/отзыва устройств и обеих смен ключей:
  количество ожидающих, наступивших повторов, заданий с сохранённой ошибкой и возраст
  старейшего. Устройство с незавершённой сменой ключа не считается повторно в очереди
  обычного создания/отзыва. Возраст задания не равен непрерывному времени ошибки.
- Просроченные подписки в состоянии active: сколько ожидает обработки и сколько ждёт
  старейшая. Это состояние базы, а не проверка работающего соединения на VPN-узле.
- Серверы по протоколам: зарегистрированные/включённые, доступные для новых назначений,
  сохранённые API-ошибки и успешные проверки не старше суток. Вместимость считается
  по той же модели занятых подписок, что и подбор сервера. Серверы draining обслуживают
  прежние привязки, но не считаются доступными для новых назначений.
- Формат ENCRYPTION_KEY, наличие настроек сайта/Telegram/Stars и опубликованных тарифов.
  Значения ключей, токенов, домены, имена клиентов/серверов и тексты ошибок не возвращаются.

Настройки оплаты отмечаются как заполненные, а не проверенные у платёжного сервиса.
Проверка формата ключа не расшифровывает все записи; для этого используется проверка
архива по BACKUP.md. Сверка ЮKassa может содержать ещё не оплаченные счета: сама по себе
эта очередь не означает неисправность провайдера.

## Наблюдение за worker

Worker фиксирует начало, успешное завершение и ошибку своего цикла только в памяти
**текущего процесса**. После запуска приложения данные сбрасываются: старый снимок базы
не может сделать только что запущенный worker «здоровым». API не запускает цикл ради отчёта.

| Состояние | Значение |
|---|---|
| disabled | Фоновые задачи выключены настройками |
| not_observed | В этом процессе цикл ещё не начинался |
| busy | Цикл выполняется, прошло не больше 180 секунд |
| recent_success | Успешный цикл завершился не больше 180 секунд назад |
| slow | Текущий цикл длится больше 180 секунд |
| stale | Нет свежего успешного цикла либо метки времени несогласованы |
| failed | Последний завершённый цикл завершился ошибкой |

Долгий цикл может ожидать панель, обрабатывать много заданий или упираться в блокировку.
Предупреждение не определяет причину и не доказывает, что процесс умер. Отдельного
наблюдения за bot polling, внешним scheduler и другими процессами в этом отчёте нет.
Несколько uvicorn workers по-прежнему не поддерживаются.

Если задания выдачи/устройств или просроченный отзыв ждут больше 10 минут, показывается
предупреждение. Есть также предупреждения по ошибкам очередей, выключенному worker,
непроверенным серверам, отсутствию назначения/тарифов и неполным настройкам.

`local_checks_ok` означает только отсутствие замечаний в этих локальных проверках.
`needs_attention` означает наличие предупреждений. Ни один статус не подтверждает:
реальный VPN-трафик/скорость, успешный платёж/чек, работу бота, целостность всей базы,
свежесть резервной копии или успешное восстановление на VPS. Эти границы явно записаны
в `scope`; JSON не содержит пользовательских идентификаторов, секретов и ответов провайдеров.

## CLI без вывода токена

Docker-образ v0.023 включает `scripts/status.py`. Скрипт обращается только к буквальному
loopback-адресу HTTP (127.0.0.1 или ::1), не использует proxy-переменные и не следует
редиректам. Он читает существующий ADMIN_TOKEN из окружения контейнера; не передавайте
ключ аргументом команды. При нестандартном порте укажите его в `--url`.

Для установки через установщик:

```bash
cd /opt/pushok-vpn
project=$(python3 -c 'import json; print(json.load(open("installer.json"))["project"])')
docker compose --project-name "$project" --env-file "$PWD/.env" -f compose.install.json exec -T shop python scripts/status.py --url http://127.0.0.1:8000/shop
```

Из Python-установки используйте `python3 scripts/status.py --url http://127.0.0.1:8000/shop
--token-file /root/shop-admin-token` (в одну строку). Файл токена должен иметь права 0600.
CLI не читает `.env` и не импортирует приложение, не создаёт базу и не запускает worker.
Он получает отчёт **от работающего процесса**, поэтому видит его наблюдение за worker.

Коды завершения: 0 — local_checks_ok, 1 — needs_attention, 2 — отчёт не получен.
При сетевой ошибке/отказе авторизации/редиректе тело ответа и токен не выводятся.
В режиме обслуживания API закрыто, поэтому CLI также завершится с кодом 2; для проверки
подготовленного обновления используйте `/shop/health` и `upgrade.py status`.

Проверки API сервера выполняются отдельно явной кнопкой в разделе серверов; сам отчёт
их не запускает. Существующий `scripts/check.py` остаётся инструментом сетевой проверки
конфигурации (он может обращаться к панелям и Telegram) и не заменяется локальным отчётом.
Проверку покупки и VPN-подключения проводите по STAGING.md.

Новый релиз не добавляет переход установщика v0.022 → v0.023. `--upgrade` в bootstrap
сохраняет только ранее поддержанный переход v0.021 → v0.022 и скачивает именно исходники
v0.022; команды этого перехода описаны в UPGRADE.md. Диагностика не переключает версии
или volumes автоматически.
