# Очередь остановок MTProxy — v0.035

В админке появился раздел «Очередь остановок MTProxy» с явным обновлением.
Он показывает состояние базы на момент чтения; это не мониторинг реального узла.
Истечение срока не означает остановку спонсора и не освобождает площадку.

## Фильтры и порядок

- Требуют остановки: active с плановым сроком меньше либо равным времени снимка.
- Предстоящие: active с будущим сроком, без ограничения одним днём.
- На паузе: paused, в том числе с нулевым остатком; площадка удерживается.
- Все незавершённые: первые три группы; finished не включается.

Плановый срок = начало текущего активного отрезка + бюджет − ранее учтённое время.
Просрочка = максимум из нуля и разницы времени снимка со сроком.
Счётчики всех трёх групп видны при любом фильтре. По 20 записей на страницу.
В общем списке сначала идут просроченные, затем предстоящие, затем паузы;
внутри групп используется срок, время изменения и ID заявки для стабильного порядка.
Это страницы текущего снимка, а не зафиксированный курсор между отдельными запросами:
при изменении размещений или времени состав страниц может измениться.

## Ручное подтверждение

После обновления проверьте фактический спонсорский канал в Telegram и выполните
нужные ручные действия на узле. Затем сохраните подтверждение из очереди.
Используются существующие start/pause/resume/finish и их ограничения; очередь
не создаёт отдельного способа обхода оплаты, версий или занятости площадки.
Здесь отображаются только уже начатые незавершённые размещения, поэтому start
в очереди не предлагается. При нулевом остатке паузы продолжение не предлагается.

UUID запроса сохраняется при потере ответа. Устаревшая версия даёт 409:
обновите очередь и сверьте реальное состояние до повторного подтверждения.
После успешного действия очередь обновляется. Чтение не списывает время, не
добавляет событий в журнал и не освобождает место. Ручные действия по-прежнему
фиксируются в журнале размещения. Автор admin относится к общему ADMIN_TOKEN.

Список обновляется кнопкой, при смене фильтра/страницы и после успешной команды.
Автоматического опроса и фоновой остановки нет. Время снимка и план остановки
показываются во времени браузера. При неудачном обновлении прежние строки и команды
удаляются; выход очищает очередь и игнорирует запоздалые ответы.

## API

GET /api/admin/ads/stop-queue?view=due&page=1 относительно PUBLIC_URL своей установки.
Требуется ADMIN_TOKEN. view: due (по умолчанию), upcoming, paused, all.
page: целое число 1–100000. Некорректные значения дают безопасный 422.

Ответ: requests, counts={due,upcoming,paused}, total, page, page_size=20, view,
generated_at (Unix-секунды UTC). Каждая строка содержит ID/версию заявки, канал,
user_id, state модерации, сумму/часы, общедоступную сводку payment, сводку placement,
queue_status и overdue_seconds. Основания проверки, банковские ID и действия
размещения в очередь не включаются. Клиентского маршрута для этой очереди нет.

Один момент времени используется для счётчиков, фильтра, срока и остатка всех строк;
чтение выполняется в одной транзакции SQLite. Схема базы и формат копии не меняются.
Docker-проверка использует синтетические размещения и локальный HTTPS, без команд
реальному Telegram-узлу, банковских операций или подтверждения рекламных показов.
