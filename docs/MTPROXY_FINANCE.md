# Сводка ручного учёта рекламы — v0.038

Раздел админки «Сводка рекламы и расходы» объединяет записи поступлений/полных
возвратов, расходы и состояние оплаченных заявок. Банковский API не вызывается,
деньги не перемещаются. Данные отражают записи владельца, а не автоматическую
сверку банка, реальный рекламный показ или юридическую отчётность.

## Что именно считается

| Показатель | Основание |
| --- | --- |
| Поступления | receipt.amount по времени receipt.created в рекламном журнале |
| Возвраты | refund.amount по времени refund.created в том же журнале |
| Поступления минус возвраты | Разность двух предыдущих показателей за период |
| Учтённые расходы | amount действующих записей recorded по указанной incurred_at |
| Остаток после учтённых расходов | Поступления − возвраты − учтённые расходы |
| Оплаченные заявки сейчас | Все заявки с receipt без учтённого полного refund, независимо от периода |

Период полуоткрытый: [start, end). При совпадении с началом запись включается,
с концом — исключается. Обе границы задаются вместе; пустые границы дают последние
30 суток до момента снимка включительно, максимальная длина — 366 дней.
API использует Unix-секунды UTC, форма ввода/отображение — часовой пояс браузера.

Для денег дата означает время сохранения ручного подтверждения, а не дату
проведения операции банком. Для расхода используется дата, введённая владельцем.
Эти основания явно различаются. Если подтверждение или исправление добавлено позже,
прошлый отчёт может измениться; закрытых неизменяемых финансовых периодов здесь нет.
Расход исключается из всех периодов по текущему состоянию записи, а не считается
поступлением в дату исправления. Сводка не заменяет банковскую выписку.

Остаток может быть отрицательным. Он **не называется чистой прибылью**:
полнота расходов, комиссии, налоги, иные обязательства и учётная политика
не проверяются автоматически. is_net_profit всегда false, source=manual_ledger.
VPN-заказы и их суммы в рекламную сводку не включаются.

## Обязательства и размещения

Срез current_paid_requests относится к текущему моменту, а не к выбранному периоду:

- not_started — оплаченная заявка без начатого размещения, включая бронь.
- active — запуск учтён вручную, остановка ещё не подтверждена.
- paused — пауза с сохранённым неоказанным остатком.
- early_stopped — остановка подтверждена раньше полного бюджета времени.
- completed — учтён весь бюджет и подтверждена остановка.

Каждая группа содержит requests, contract_amount и remaining_seconds.
Сумма заявок не является автоматически заработанной выручкой или суммой возврата.
Частичные возвраты и расчёт денежной компенсации за остаток пока не реализованы.
Истечение таймера при active не переводит запись в completed. Раннее finished
с остатком не считается полным выполнением. Текущие полные возвраты исключают заявку
из этих групп, даже если в выбранном прошлом периоде были записаны поступления.
Это объясняет отличие исторических сумм и текущих состояний.

## Учёт расходов

Владелец вводит целую сумму в рублях, категорию (server/commission/marketing/other),
дату уже понесённого расхода, уникальный ID операции/документа и основание/источник.
Сумма: 1–1 000 000 ₽. Будущая дата запрещена; произвольная категория не принимается,
для иных затрат используется other и описание. Не записывайте ФИО, пароли,
банковские реквизиты или секреты узла в ID/примечания.

ID нормализуется в нижний регистр, допускает 3–120 ASCII-символов по тем же правилам,
что рекламные платежи (буквы/цифры, : . _ / -). Уникальность проверяется среди
действующих расходов этой установки. Добавьте префикс источника, если нужно отличать
одинаковые номера разных систем. Валюта — только RUB; конвертации нет.

Ошибочную запись можно исключить действием void по текущей версии, указав причину.
Исходная сумма, дата и основание сохраняются, причина исправления остаётся в журнале.
Это корректировка учёта, **не возврат денег**. Исключённые записи видны в списке,
но не вычитаются из остатка. После исключения можно создать исправленную запись
с новым operation_id и тем же ID документа. Прямое редактирование/удаление не доступно.

История хранится в ads_expense_actions; изменения также фиксируются в ads_events.
Автор admin означает общий ADMIN_TOKEN: именованные роли ещё не введены.
Расходы и их основания рекламодателю не выдаются.

## API

Все пути относительны PUBLIC_URL своей установки (включая /shop).
Требуется ADMIN_TOKEN; изменения наследуют проверку Origin и общие ограничения.

| Метод и путь | Действие |
| --- | --- |
| GET /api/admin/ads/finance?start=…&end=…&page=1 | Сводка и до 20 записей расходов |
| POST /api/admin/ads/expenses | Учесть расход |
| POST /api/admin/ads/expenses/{id}/void | Исключить ошибочную запись |

Создание: operation_id (UUID), amount, category, incurred_at, reference, note.
Исключение: operation_id (новый UUID), version, note (причина).
Одинаковый UUID и то же содержимое возвращают текущую запись без повторного действия,
включая повтор создания после исключения. Другие данные/действие/запись под тем же UUID
дают 409. Действующий дубликат ID документа, будущая дата и старая версия — 409.
Некорректный ввод — безопасный 422, неизвестная запись — 404.

GET возвращает period, generated_at, currency, source, cash, expenses,
cash_after_recorded_expenses, is_net_profit=false и current_paid_requests.
expenses содержит amount, recorded_count, voided_count, entries, total, page,
page_size=20. Счётчики/суммы относятся ко всему выбранному периоду, не к одной странице.
В строках есть исходное основание note и причина void_reason. page: 1–100000.
Допустимые Unix-границы: от 0 (start) / 1 (end) до 32503680000; расход — от 1,
с дополнительной проверкой отсутствия будущей даты. Эти пределы технические.

Сводка читает один снимок SQLite и использует один момент времени для остатка
активных размещений. Чтение не добавляет событий и не изменяет расходы/размещения.
Пагинация упорядочена по дате расхода и ID; отдельные запросы могут отражать новые
данные. Изменения формы во время сохранения не стираются ответом предыдущей записи.
Выход очищает сводку/поля/намерения, поздние ответы не восстанавливают их.

## Обновление и проверка

Добавлены пустые ads_expenses и ads_expense_actions с ограничениями и индексами.
Прежние данные не меняются. Они включены в зашифрованную копию и восстановление;
сессии после восстановления удаляются. Для сравнения со старой схемой только
новые пустые таблицы исключаются из хеша, их наличие проверяется отдельно;
непустые записи всегда участвуют в контрольной сумме.

Модульные проверки покрывают границы периода, возвраты в другой период, статусы
размещений, отрицательный остаток, повторы, коррекции, конкурирующие запросы,
приватность, миграцию и настоящий зашифрованный архив. Docker проверяет синтетические
поступление/возврат, расход, исправление, сводку без записи и восстановление.
Реальный банк, Telegram-узел, рекламные показы и чистая прибыль не проверяются.

остаётся отдельной задачей с владельцем по ROADMAP.md.
