# Площадки и ручные подтверждения размещений — v0.034

Кабинет учитывает действия владельца после проверки настоящим Telegram-клиентом.
Он не управляет Telegram-аккаунтом/узлом, не переключает спонсора и не измеряет
показы, переходы или подписчиков. Отметка «проверено» означает утверждение владельца,
а не результат автоматического запроса. Учёт поступлений описан в MTPROXY_PAYMENTS.md.

## Площадки

В разделе админки «Площадки MTProxy» нажмите «Обновить площадки» или создайте новую.
Задайте публичное название, основание проверки без секретов и отметки проверки/
разрешения новых запусков. По умолчанию форма новой площадки выключена и не проверена.
Реестр вмещает до 100 площадок. Ненужные площадки выключаются, история не удаляется.
Название сохраняется снимком в размещении: переименование не меняет историю клиента.

Разрешение запусков не включает реальный прокси; оно только разрешает действия
кабинета. Выключение не останавливает действующее размещение. Снять отметку проверки
при активном размещении нельзя: сначала подтвердите паузу или остановку.
Пауза сохраняет исключительное занятие площадки; выключенная/непроверенная площадка
не позволяет продолжить показ до повторной настройки владельцем.
Публичное название видно рекламодателю; основания, ID площадки и журнал проверок
доступны только администратору. Секреты узла в этом реестре не нужны.

## Порядок размещения

1. Одобрите заявку и учтите проверенное поступление полной суммы.
2. Обновите очередь, убедитесь, что площадка включена, проверена и свободна.
   Выполняйте ручные изменения узла последовательно: кабинет не блокирует действия
   другого человека за пределами магазина. При конфликте 409 проверьте фактического
   спонсора и актуальную заявку, прежде чем сохранять новое подтверждение.
3. Настройте спонсора штатными средствами выбранного узла, проверьте канал настоящим
   Telegram-клиентом. Только затем сохраните подтверждение фактического запуска,
   указав площадку и основание. Запись в кабинете сама не меняет узел.
4. При остановке показа подтвердите паузу. Она сохраняет оставшееся время и удерживает
   площадку. Продолжение снова требует фактической проверки владельцем.
5. При окончании срока реально остановите/переключите спонсора штатными средствами,
   проверьте результат и подтвердите остановку в кабинете. Только это освобождает место.

Состояния: нет размещения → active → paused → active; из active/paused можно
перейти в finished. Одна заявка допускает одно размещение; повторный запуск
завершённой заявки запрещён. Новая заявка на тот же канал после завершения разрешена,
завершённые размещения не расходуют лимит пяти открытых заявок.

Одна площадка занята максимум одним active/paused размещением. Это ограничение
журнала, защищённое транзакцией и уникальным индексом SQLite. Будущих бронирований
и автоматического согласования команд с реальным узлом в этом выпуске нет.

## Время и неоказанный остаток

Бюджет = часы снимка тарифа × 3600. Поступление и модерация время не расходуют.
Счёт начинается с сохранённого подтверждения запуска по часам сервера.
Пауза фиксирует использованные секунды; длительность паузы из бюджета не вычитается.
Продолжение рассчитывает новый ожидаемый срок остановки из остатка.
Отрицательное движение часов не уменьшает уже сохранённое время; синхронизацию часов
сервера нужно поддерживать штатными средствами ОС.

used_seconds ограничен бюджетом тарифа, remaining_seconds не бывает отрицательным.
Это расчёт времени из последнего ручного подтверждения, а не измерение реального показа.
До очередной проверки он предполагает, что подтверждённое состояние не изменилось.
При remaining_seconds=0 активное размещение получает attention_due=true и сообщение
о требуемой остановке. Состояние остаётся active, площадка остаётся занятой.
Worker не объявляет реальную остановку по одному лишь времени.

Ранняя остановка сохраняет неоказанный остаток. finished означает подтверждённую
остановку, а не обязательное выполнение всего оплаченного срока. Автоматической
компенсации, частичного возврата или переноса остатка в другую заявку пока нет.
Полный возврат можно учесть только после остановки, включая выход из паузы через
finished. Реальный возврат выполняется отдельно во внешнем сервисе.

## API

Все пути относительны PUBLIC_URL своей установки, в том числе /shop.
Управление требует ADMIN_TOKEN и общей проверки Origin.

| Метод и путь | Назначение |
| --- | --- |
| GET /api/admin/ads/sites | Все площадки с закрытыми основаниями и занятостью |
| PUT /api/admin/ads/sites/{uuid} | Создать площадку с version=0 или изменить по текущей версии |
| POST /api/admin/ads/requests/{uuid}/placement/start | Подтвердить запуск |
| POST /api/admin/ads/requests/{uuid}/placement/pause | Подтвердить паузу |
| POST /api/admin/ads/requests/{uuid}/placement/resume | Подтвердить продолжение |
| POST /api/admin/ads/requests/{uuid}/placement/finish | Подтвердить фактическую остановку |

Площадка: version, name, enabled, verified, note. При потере ответа PUT повторите
тот же UUID площадки: второй объект не создаётся; при 409 обновите список и откройте
сохранённую площадку для редактирования. Изменения требуют актуальной версии.

Подтверждение: operation_id (UUID), request_version, payment_version,
placement_version, note, checked=true. Для start дополнительно обязательны site_id
и site_version; в остальных действиях площадка не заменяется. Версия размещения
равна 0 до запуска, затем увеличивается с каждым действием.
Повтор исходного UUID и того же содержания возвращает текущий статус без нового
действия, включая повтор после остановки/возврата. Изменённое содержание — 409.
Версии, одобрение, поступление, занятость и изменение проверяются в одной транзакции;
конкурирующие запуск/возврат не оставляют активную возвращённую заявку.

В своих заявках клиент получает placement: state, version, site_name, started,
finished, updated, allocated_seconds, used_seconds, remaining_seconds,
expected_stop_at, attention_due, verification=manual либо null до запуска.
Основания и действия ему не выдаются. В административной заявке доступны последние
50 действий action/note/created; полный журнал хранится в базе. Общий ADMIN_TOKEN
фиксирует автора admin, именованные сотрудники пока не поддерживаются.

## Обновление и восстановление

Добавлены ads_sites, ads_placements и ads_placement_actions без заполнения по умолчанию.
Индекс ads_open_channel заменён поисковым: открытые каналы теперь проверяются в
BEGIN IMMEDIATE с учётом завершённых размещений. Это позволяет повторить заказ на
тот же канал после завершения, сохраняя атомарный отказ дубликата открытой заявки.
В старых таблицах строки и столбцы не меняются.

Архив сохраняет площадки, состояния, бюджет, остаток и действия. Восстановление
не освобождает занятую площадку и не отправляет команды узлу. После восстановления
владелец сверяет реальный показ и подтверждённое состояние: по архиву невозможно
автоматически установить, работал ли внешний прокси во время простоя магазина.
Для сравнения старой схемы только три новые пустые таблицы исключаются из хеша,
непустые таблицы всегда входят в контрольную сумму. Пустые таблицы также проверяются
на наличие; сессии после восстановления удаляются по общему правилу.

Тесты используют искусственные часы, локальный HTTPS и синтетические подтверждения.
Docker проверяет настоящее обновление/откат и восстановление архива, без реального
Telegram-узла, показов или банковских операций.
Следующий этап — бронирование будущих периодов, удобная очередь остановок и
подтверждённая приёмка первого настоящего MTProxy-узла; адаптер автоматизации
возможен только после выбора и проверки конкретного интерфейса управления.
