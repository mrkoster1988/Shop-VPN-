# Дополнительные панели: 3x-ui и WGDashboard

Кодовый этап, пока без приёмки на чистой VPS. Текущий загрузчик v0.054 не содержит этого мастера. Команды ниже выполняются из актуальных исходников Shop. Панели сторонние, устанавливаются отдельно от контейнеров магазина. Их данные не входят автоматически в резервную копию Shop: отдельно сохраняйте Compose и тома панелей.

## Выбор при установке

```bash
sudo python3 scripts/install.py --panels both
```

`both` — обе панели, `xui` — только 3x-ui, `wgdashboard` — только WireGuard-панель; без параметра устанавливается только Shop. Для уже установленного магазина запускайте отдельный мастер:

```bash
sudo python3 scripts/install_panels.py --panels both
```

Мастер спросит полный адрес официального образа с digest (`@sha256:` и 64 символа), а для WGDashboard — публичный IPv4 VPS. Digest скопируйте из официального реестра выбранного релиза. Проверенный набор версий ещё не утверждён; не используйте произвольные старые версии. Плавающие `latest`/`main` мастер не принимает. Флаг `--plan` у отдельного мастера выводит Compose без установки. Существующий каталог или занятые порты останавливают установку; автоматической переустановки нет. После частичного сбоя используйте сохранённый Compose и диагностику Docker, не удаляйте тома.

## Порты и первый вход

| Компонент | Управление | VPN-трафик |
|---|---|---|
| 3x-ui | localhost:2053 | TCP 8443 |
| WGDashboard | localhost:10086 | UDP 51820 |

На компьютере создайте туннель (на телефоне — аналогичное SSH port forwarding):

```bash
ssh -L 2053:127.0.0.1:2053 -L 10086:127.0.0.1:10086 USER@SERVER_IP
```

Откройте `http://localhost:2053` или `http://localhost:10086` на устройстве с туннелем. Задайте свои учётные данные, настройте двухфакторный вход. Начальные параметры входа сверяйте с документацией выбранной версии образа. Административные порты не нужно открывать всему интернету. Для постоянного удалённого API настройте HTTPS через существующий прокси, не отключая проверку сертификата в Shop.

## 3x-ui → Shop

Подробно: [подключение по API](THREEXUI_API.md).

1. В панели настройте административный логин, пароль и путь панели.
2. Создайте inbound VLESS на TCP 8443; выберите транспорт и TLS/REALITY, заполните параметры по официальной инструкции панели. Порт 443 уже может использовать HTTPS магазина.
3. Добавьте пробного клиента и проверьте его ссылку в VPN-приложении. Откройте только выбранный VPN-порт в firewall хостера.
4. В Shop: «Серверы» → новый VLESS-сервер → режим Legacy → адрес панели с её путём, логин, пароль, inbound ID и шаблон ссылки с `{uuid}`. Параметры транспорта и защиты в шаблоне должны совпадать с inbound.
5. Проверьте API и затем включите сервер. Пройдите покупку, выдачу, продление и отзыв.

Если 3x-ui уже работает на pushok.shop, пропустите её установку и начните с подключения API. Обновление панели не выполняется установщиком Shop. В контейнерном варианте дополнительные inbound-порты нужно явно добавить в Compose. Встроенный Fail2ban в нашем профиле выключен: не считать ограничения IP активными.

## WGDashboard → Shop

1. Проверьте поддержку WireGuard ядром VPS. Контейнер использует NET_ADMIN; возможности ядра и ограничения виртуализации Docker не заменяет.
2. В WGDashboard проверьте интерфейс `wg0`, порт 51820, адресную подсеть, DNS, публичный Endpoint, маршрутизацию и NAT. Не выбирайте подсеть, пересекающуюся с сетью VPS или другими VPN.
3. Запустите интерфейс, создайте пробного peer, скачайте конфигурацию и подтвердите прохождение трафика. Разрешите UDP 51820 в firewall хостера. Сгенерированный интерфейс сам по себе не доказывает работоспособность VPN.
4. Включите API в настройках WGDashboard и создайте отдельный API-ключ для магазина.
5. В Shop: новый WireGuard-сервер → WGDashboard → адрес панели без `/api`, API-ключ и интерфейс `wg0`. Проверьте API перед включением сервера.
6. Проверьте выдачу, повтор операции без второго peer, продление и отключение по сроку. Часовой пояс контейнера UTC; такой же укажите для необязательного задания истечения на панели.

Мастер запускает контейнеры, но не создаёт бизнес-настройки в Shop автоматически. HTTPS, API-ключи, inbound, сетевой доступ и реальные оплаты требуют завершения настройки. Remnawave остаётся вариантом подключения существующей панели.
