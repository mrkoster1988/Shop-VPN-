# SOO Pushok — подготовка WireGuard для существующих пользователей

Этот блок расширяет существующую `flow_auto_provision`, а не создаёт второй механизм выдачи.
Работает только с учётными записями самого Shop. Связь с Pushok ID / MTProxy и автоматическая
синхронизация с авторизацией Android требуют отдельного интеграционного этапа.

## Владелец магазина

В разделе **Pushok Flow · автоматический WireGuard** доступны политика срока (1–30 дней),
пожизненный общий лимит (1–100000), число подходящих аккаунтов, состояние очереди и
кнопка подготовки очередной партии. Политика по умолчанию отключена. Включение требует
HTTPS, заполненных условий доступа и WGDashboard с защищённым заданием истечения.
Операции владельца используют штатную авторизацию сотрудников и аудит.

- GET /api/admin/flow/wireguard/auto/batch — read-only предварительная оценка.
  Выдаёт счётчики, версию политики и до 50 ID кандидатов; не выдаёт email,
  Telegram ID, ключи или конфигурации.
- POST /api/admin/flow/wireguard/auto/batch — `{"version":2,"user_ids":[11,12]}`.
  Обрабатывает только явно переданные уникальные ID, 1–50 за запрос.
  Повтор прежнего тела не выбирает следующих пользователей.
  Если часть партии не была принята из-за квоты/ёмкости, повтор проверяет
  только ту же партию. Неуспешные кандидаты могут стать доступными позднее.
- При изменении политики старый запрос получает 409. При выключении
  автовыдачи не принимаются новые партии. При недостаточной ёмкости
  сохраняются только успешно зарезервированные заявки.
- Наличие любого WireGuard-профиля (в том числе истёкшего), предыдущей
  автовыдачи или незавершённого WG-заказа исключает повторную стартовую выдачу.

Успешное резервирование создаёт pending-подписку и одну строку durable-очереди,
не вызывает API панели и не создаёт платёж. Фоновый обработчик применяет существующий
идемпотентный путь с тем же ID и отдельным приватным ключом; клиент видит доступ
только после подтверждённой выдачи. Срок стартового доступа отсчитывается от
резервирования, а не от первого подключения. Квота используется и ожидающими
заявками; истёкшие записи не освобождают её автоматически.

## Приёмка перед включением на реальном сервере

- Python: права владельца, read-only preview, лимиты, повтор, отдельная идентичность,
  отсутствие перезаписи покупок, отключённая политика.
- Node: только явная партия, отсутствие автоповтора следующей партии, отмена доступа
  к UI после выхода, блокировка при несохранённой политике.
- Проверить серверное отключение peer по сроку, подтверждение API WGDashboard,
  работу при сбое/перезапуске и совместимость с версией Android Flow.
- Настроить допустимый срок и квоту; начать с небольшой партии и проверить трафик,
  затем увеличивать лимит. Не включать выдачу для всех до проверки узла.
- Этот код не внедряет новую схему БД и не является подтверждением production-выдачи.
